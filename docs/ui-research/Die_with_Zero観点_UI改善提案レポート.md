# Die with Zero観点のUI改善提案レポート

## 目的

退職後生活シミュレーションアプリについて、ユーザーの主目的を次のように定義する。

- 90歳まで資産を枯渇させない
- ただし資産最大化が目的ではない
- 健康寿命期である60〜69歳、または60〜72歳に、旅行・趣味・家族イベントなどの体験支出を最大化したい
- 米国株オプション利益は不確実性があるため、基本生活や最低残高維持の前提には置きすぎない

この目的に対して、現行アプリは資産寿命・指定年齢残高・資産活用額・比較表をすでに持っている。一方で、「健康寿命期にあといくら自分のために使ってよいか」を直接判断するには、既存指標の見せ方と一部の補助指標が不足している。

## 現行アプリで確認できた既存機能

### 基本情報

すでに以下の入力項目が存在する。

- 指定年齢時点残高を見る年齢: 90歳
- 指定年齢時点の目標残高: 500万円
- 目標残高に向けた計画取り崩し: OFF
- 流動資金最低保持額: 300万円

したがって、「90歳最低残高を入力する機能」を新設する必要はない。既存の「指定年齢時点の目標残高」を、Die with Zero用の判定基準としてもっと明示的に使うべきである。

### 比較タブ

比較タブには、すでに以下のような任意期間集計がある。

- 資産活用 開始年齢
- 資産活用 終了年齢
- 指定期間の資産活用額
- 指定期間の年平均余力
- 指定期間末残高
- 指定年齢残高
- NISA未実行
- 追加投資
- 普通口座オプション利益と税社保増分

これは方向性として非常によい。次の改善では、ここに「目標残高との差額」と「楽しみ支出」を加えるのが自然。

### 特別支出

現在、以下のような支出が登録されている。

- 旅行 国内
- 旅行 ベトナム
- 住宅修繕

ただし、旅行系のカテゴリが「生活維持」になっている。現行ダッシュボードでは「60〜72歳 楽しみ支出」が0円になっていたため、Die with Zero観点の分析では実態より楽しみ支出が少なく見える可能性が高い。

## 問題点

### 1. 目標残高が「入力されているだけ」に見えやすい

90歳目標残高500万円は入力済みだが、比較表では「指定年齢残高」として残高そのものは見える一方、目標残高との差額が直接見えない。

ユーザーが知りたいのは、単なる90歳残高ではなく、

```text
90歳時点で500万円を残したうえで、あとどれくらい60代に使えるか
```

である。

### 2. 「楽しみ支出」が意思決定指標として弱い

Die with Zero目的では、生活費や税社保の不足を埋めることよりも、健康な時期にどれだけ体験・思い出に使えたかが重要である。

現行でも特別支出カテゴリはあるが、カテゴリ設定ミスがあるとダッシュボード上の「楽しみ支出」が0円になり、判断が歪む。

### 3. オプション利益の不確実性が意思決定に混ざりやすい

比較表には普通口座オプション利益・税社保増分・証拠金不足停止が表示されている。これは重要な情報だが、ユーザーが追加支出を判断する際には、以下を分けて見たい。

- オプション利益なしでも実行できる支出
- オプション利益が半分でも実行できる支出
- オプション利益が予定通り出た場合だけ実行する支出

現状では、上振れ原資と安全原資の区別がUI上でまだ弱い。

## 改善提案

## 1. 「目標残高との差額」列を比較表に追加する

比較表に次の列を追加する。

- 指定年齢目標残高
- 目標残高との差額
- 目標達成判定

計算式:

```text
目標残高との差額 = 指定年齢残高 - 指定年齢時点の目標残高
```

表示例:

| シナリオ | 90歳残高 | 90歳目標残高 | 目標残高との差額 | 判定 |
|---|---:|---:|---:|---|
| iDeCo 10年 | 3,128万円 | 500万円 | +2,628万円 | 達成 |
| iDeCo 5年 + オプション10万 | 2,765万円 | 500万円 | +2,265万円 | 達成 |

この列により、ユーザーは「資産が多く残るか」ではなく、「目標を守ったうえで余力がどれくらいあるか」を判断できる。

## 2. ダッシュボードに「追加支出候補額」カードを追加する

ダッシュボード上部に、既存の指定年齢目標残高を使ったカードを追加する。

表示案:

```text
90歳目標残高との差額
+2,265万円

目標500万円を上回る余力。
60〜69歳・60〜72歳の追加支出候補として検討可能。
```

注意点として、この差額を「そのまま全額60代に使える」と表現しない。60代前半で使うと将来運用益も失うため、表示名は「追加支出候補額」または「余力目安」がよい。

## 3. 健康寿命期の「追加支出シミュレーター」を追加する

比較タブまたは特別支出タブに、簡易的な追加支出テスト機能を置く。

入力項目:

- 期間: 60〜69歳 / 60〜72歳 / 任意
- 年額追加支出: 50万円 / 100万円 / 150万円 / 200万円 / 任意
- カテゴリ: 楽しみ / 家族支援 / 住宅・車 / 医療・介護 / 予備

出力:

- 追加支出総額
- 90歳残高
- 90歳目標残高との差額
- 枯渇有無
- 期間末残高
- 期間中最低流動資金

表示例:

| 追加支出 | 対象期間 | 90歳残高 | 目標差額 | 判定 |
|---:|---|---:|---:|---|
| 年100万円 | 60〜69歳 | 1,850万円 | +1,350万円 | 実行余地あり |
| 年150万円 | 60〜69歳 | 1,210万円 | +710万円 | 注意しつつ実行可 |
| 年200万円 | 60〜69歳 | 420万円 | -80万円 | 目標割れ |

この機能は、ユーザーが特別支出を1件ずつ手入力する前の粗い検討に使う。

## 4. 特別支出カテゴリの見直しと警告

旅行・趣味・レジャーなどの名称なのにカテゴリが「生活維持」になっている場合、軽い注意を表示する。

例:

```text
「旅行 ベトナム」は楽しみ支出として扱う可能性があります。カテゴリを確認してください。
```

カテゴリ候補:

- 楽しみ
- 生活維持
- 住宅・車
- 医療・介護
- 家族支援
- 予備・想定外

現行には「予備・想定外」が表示されていないため、追加を検討する。

## 5. ダッシュボードに「健康寿命期の支出内訳」を追加する

現在の「60〜72歳 資産活用額」に加えて、その内訳を表示する。

表示案:

- 60〜72歳 資産活用額
- うち楽しみ支出
- うち生活維持支出
- うち住宅・車
- うち医療・介護
- うち家族支援
- うち税社保

Die with Zero観点では、「資産を取り崩したか」だけでは不十分で、「取り崩した資産が何に使われたか」が重要である。

## 6. オプション利益の感度分析を追加する

米国株オプション利益について、比較タブに感度分析を追加する。

表示パターン:

- オプション利益 100%
- オプション利益 50%
- オプション利益 0%

各パターンで見る指標:

- 90歳残高
- 90歳目標残高との差額
- 60〜69歳追加支出可能額
- 税社保増分
- NISA未実行
- 証拠金不足停止

目的は、オプション利益を「生活基盤」ではなく「上振れ時の思い出原資」として扱えるようにすること。

## 7. 「計画取り崩しOFF」の意味を明示する

現在、基本情報では「目標残高に向けた計画取り崩し」がOFFになっている。

この状態では、目標残高500万円は主に判定・比較用であり、アプリが自動的に500万円まで使い切るわけではない。

基本情報またはダッシュボードに次の説明を出すとよい。

```text
現在、目標残高は判定用です。自動で目標残高まで取り崩す設定にはなっていません。
```

これにより、ユーザーが「目標残高を入れたのに、なぜもっと使う提案が出ないのか」と混乱しにくくなる。

## 優先順位

### 優先度A

1. 比較表に「目標残高との差額」「目標達成判定」を追加
2. ダッシュボードに「90歳目標残高との差額」カードを追加
3. 特別支出カテゴリの見直し、旅行系支出の「楽しみ」分類

### 優先度B

1. 健康寿命期の追加支出シミュレーター
2. 60〜69歳 / 60〜72歳の楽しみ支出合計
3. 期間中最低流動資金の表示強化
4. 入金力別の楽しみ支出可能額・税社保効率・分岐点診断

入金力を月0万 / 10万 / 20万 / 30万 / 40万 / 50万円などで横並び比較し、90歳目標残高を守りながら60〜72歳に増やせる楽しみ支出、税・社会保険料によるキャッシュアウト増、実質手残り、有効率、資産寿命を同時に表示する。中途半端な入金力が税社保増で効率低下するゾーンと、楽しみ支出を安全に増やせる分岐点をユーザーが一目で判断できるようにする。

### 優先度C

1. オプション利益100% / 50% / 0%の感度分析
2. オプション利益を安全原資と上振れ原資に分ける表示
3. 追加支出候補の自動逆算

## 期待されるユーザー体験

改善後、ユーザーは次の順番で判断できる。

1. 90歳まで資産は枯渇しないか
2. 90歳目標残高500万円を守れるか
3. そのうえで、60〜69歳または60〜72歳にどれだけ使えるか
4. その支出は生活維持ではなく、自分の楽しみ・思い出作りに使えているか
5. オプション利益が出なくても実行できる支出か、上振れ時だけ実行すべき支出か

## 結論

新しい「最低残高入力」を追加するのではなく、既存の「指定年齢時点の目標残高」をDie with Zero判断の中心に置くべきである。

現行アプリはすでに、指定年齢残高、任意期間の資産活用額、年平均余力、普通口座オプション利益と税社保増分を持っている。次の改善は、これらを「健康寿命期にいくら使ってよいか」という意思決定に接続することである。

最初に実装すべきは、比較表とダッシュボードに以下を追加すること。

- 目標残高との差額
- 目標達成判定
- 健康寿命期の楽しみ支出
- 追加支出候補額

これにより、アプリは「資産を残すシミュレーター」から、「健康なうちに納得して使うための意思決定ツール」に近づく。
