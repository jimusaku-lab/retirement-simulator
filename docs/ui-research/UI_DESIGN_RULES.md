# UI Design Rules for Finance Planner Projects

このファイルは、ファイナンスプランナー系アプリを Codex で修正・拡張する時に必ず参照する共通UIルールです。
特に `apps/retirement-life-planner` の退職後生活シミュレーション、資産レビュー、タイムバケット関連の作業では、実装前にこの内容を確認してください。

## 基本思想

- ユーザーは人間の目で画面を見て、直感的に「今どこにいるか」「次に何を押せるか」を判断する。
- UIは機能の分類だけでなく、ユーザーの作業の流れ、視線、迷いにくさを優先する。
- タブやボタンの配置を変える時は、既存の視覚的な意味を壊さない。
- 画面を縦に長くしすぎない。ナビゲーションを安易に二段化しない。
- 入力、結果確認、資産活用、楽しみ計画は、それぞれ役割が違う。色と配置で違いが自然に読めるようにする。
- ダッシュボードは入力確認の場所ではなく、退職後の資産活用について短時間で判断する意思決定画面として扱う。

## ナビゲーションとタブ

- タブはできるだけ同じ横一列に並べる。
- 不要に一段下へ落とさない。二段化は画面の見通しを悪くし、ユーザーの場所認識を壊す。
- 上位カテゴリと配下タブを横方向の並びで読めるようにする。
- 安全性シミュレーションを開いた時も、配下タブを消さない。
- 資産レビューを開いた時も、その配下の `クイック試算` と `タイムバケット` は上部の同じタブ列に表示する。
- タブを選択したら他の関連タブが消える設計にしない。関連タブは常に見えている方が、ユーザーは構造を理解しやすい。
- `安全性シミュレーション` を押して戻る時の入口は `ダッシュボード` とする。
- `ダッシュボード` は最左に置く。
- `安全性シミュレーション` と `資産レビュー` は上位カテゴリとして同列に見えるように置く。
- `資産レビュー` が安全性シミュレーション配下の末尾タブに見えないようにする。
- `マニュアル` は作業タブではない。安全性シミュレーションの並列タブに混ぜず、右上など、どこからでも開ける控えめな場所に置く。
- `シナリオ` と `データ` は前提入力ではなく管理・運用系として扱う。
- `シナリオ` は `特別支出` と `結果` の間に置かない。入力の流れと結果確認の流れを分断して見えるため。
- `シナリオ` と `データ` は、`結果` と `比較` の後ろ側にまとめる。
- `データ` は右端寄りの管理タブとして扱う。

## 色の意味

色は装飾ではなく、ユーザーが機能の種類を読み取るための意味を持たせる。

- 入力系: 薄いグリーン系
- 出力・結果系: 薄いブルー系
- 入力と結果が混在するもの: 薄いアンバー系
- 管理・運用系: 薄いバイオレット系
- 楽しみ・やりたいこと・Die with Zero 系: 明るいローズ系
- 上位カテゴリ: 背景を塗り、白抜き文字にして上位カテゴリであることを示す

避けること:

- 選択中タブだけを黒背景、他を白背景にする汎用的な色分け。
- 色の意味を無視して、単に active / inactive だけで見た目を決めること。
- `クイック試算` と `タイムバケット` の楽しみ系タブをグレーや黒系に戻すこと。
- 安全性シミュレーション配下の入力系・出力系タブの色分けを消すこと。
- `シナリオ` と `データ` を入力系のグリーンに混ぜること。

## 資産レビューと楽しみカテゴリ

- このシミュレーターの本質的な目的は、限られた時間の中で資産をどう有効活用するかを考えること。
- 有効活用とは、単に資産を残すことではなく、自分がやりたいことを見つけ、実行するための資金余地を確認すること。
- キーになるのは `楽しみ`。
- 特別支出のうち `楽しみ` カテゴリは、一目で楽しみだと分かるように薄い色でもよいので色付けする。
- `タイムバケット` で出したリストは、人生でやりたいことのリストであり、退職後シミュレーターでは特別支出の `楽しみ` カテゴリに接続する。
- `タイムバケット` の項目は、必要に応じて特別支出の `楽しみ` 項目へ転換できる設計にする。
- `クイック試算` は、楽しみに使える額を探すための機能として扱う。
- `クイック試算` と `タイムバケット` は、資産レビューの配下にある楽しみ目的の機能として、共通の明るいローズ系で統一する。

## ダッシュボード

- ダッシュボードは、結果と意思決定のための画面。
- 入力値や細かい収支をすべて並べる場所ではない。
- ダッシュボードでは、次を短時間で判断できるようにする。
  - 資産寿命は維持できているか
  - 指定年齢・目標年齢時点の残高は守れているか
  - 健康寿命期にどれだけ資産を活用できているか
  - その活用額のうち、楽しみ支出にどれだけ使えているか
- ダッシュボードの主要指標は、ユーザーが意思決定するためのものに絞る。
- 設定済みの前提確認情報は、基本情報や詳細タブ側に置く。
- 単月の最大赤字など詳細分析向きの指標は、最上段に常時出す優先度は低い。

## タイムバケット

- タイムバケットは、お金の前に「自分が本来何をしたいのか」を考える場所。
- 資金・資産の計算から一度切り離して、やりたいことに集中できる画面にする。
- 年代ボックスは、基礎情報から現在年齢を計算し、現在以降の年代だけを表示する。
- すでに過ぎた年代の箱は画面を占有するだけなので表示しない。
- 本人と配偶者がいる場合、現在該当する年代に `本人59才、配偶者56才` のように表示する。
- 項目移動は、長いリストでも見やすいようにドラッグ＆ドロップを基本にする。
- 年代間の移動だけでなく、同じ年代内での上下並べ替えもドラッグ＆ドロップでできるようにする。
- `次の年代へ` のような一方通行操作だけにしない。
- 年代は 50代、60代、70代、80代など将来側を十分に用意し、項目が画面から消えないようにする。

## マニュアルと補助導線

- マニュアルは、特定タブの作業フローではなく、全体の補助導線。
- どこからでも開ける場所に置く。
- ただし、目立ちすぎて主作業を邪魔しない。
- 右上のヘッダー操作エリアなど、常時アクセスできるが控えめな位置が望ましい。

## 実装時の注意

- UI修正では、既存の意味づけを壊す条件分岐に注意する。
- 例えば `activeTab !== "dashboard"` のような条件で、必要なタブまで消していないか確認する。
- タブの表示条件を変更したら、以下を必ず確認する。
  - ダッシュボード表示中も安全性シミュレーション配下のタブが見えるか
  - 資産レビュー表示中に `クイック試算` と `タイムバケット` が見えるか
  - `安全性シミュレーション` を押すとダッシュボードに戻るか
  - 色分けが入力・出力・混在・楽しみの意味に沿っているか
  - マニュアルが作業タブ列に混ざっていないか
- 画面確認はビルド成功だけで終わらせない。ブラウザ上でナビゲーションと色を確認する。

## Codexへの指示

このプロジェクトでUIやデザインを触る時、Codexは次を守ること。

- 実装前にこのファイルを読む。
- ユーザーが過去に決めた配置・色・意味づけを勝手に単純化しない。
- 「技術的に整理されている」ことより、「人間の目で直感的に分かる」ことを優先する。
- タブや色を変更する場合は、階層、作業目的、ユーザーの視線の流れを説明できる状態で行う。
- 既存UIを壊した可能性がある時は、すぐにブラウザで確認する。
