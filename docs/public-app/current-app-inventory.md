# 現行版棚卸し

作成日: 2026-05-19

対象コード: `apps/retirement-life-planner-public`

この棚卸しは、一般向け版の作業場所へ複製した現行アプリを対象にしている。現行安定版 `apps/retirement-life-planner` には手を入れない。

## 1. 全体構成

現行アプリは、Vite、React、TypeScript、Zustand、Recharts、Tailwind CSS で構成されている。

主要ファイル:

| 領域 | ファイル | 役割 |
|---|---|---|
| アプリ本体 | `src/App.tsx` | 画面、タブ、保存、入出力、主要UIの大半 |
| 状態管理 | `src/store/usePlanStore.ts` | Zustand persisted store、正規化、バックアップ、シナリオ操作 |
| 型定義 | `src/types.ts` | 世帯、資産、収入、税社保、シナリオ、結果型 |
| サンプル | `src/data/sampleData.ts` | 初期サンプル世帯と比較シナリオ |
| 月次・年次計算 | `src/lib/simulation.ts` | 資産推移、収支、取り崩し、税社保反映 |
| 税社保 | `src/lib/taxEngine.ts` | 所得税、住民税、国保、後期高齢者医療、介護保険等の概算 |
| 退職所得 | `src/lib/retirementIncome.ts` | iDeCo一時金、退職所得控除、重複ルール周辺 |
| 年金 | `src/lib/pensionPlanner.ts` | 年金受給開始、繰上げ・繰下げ、加給年金 |
| 資産活用 | `src/lib/flexibleFreeCash.ts` | 健康寿命期の自由資金、資産活用ウォーターフォール |
| 資産レビュー | `src/lib/assetUseAnalysis.ts` | 目標残高分析、追加支出試算、入金力診断 |
| シナリオ差分 | `src/lib/scenarioDiff.ts` | 比較タブの差分要約 |
| タイムバケット | `src/components/TimeBucketPlanner.tsx` | やりたいこと、年齢箱、特別支出変換 |

## 2. 画面構成

現行アプリは、主に次の画面群で構成されている。

| 画面 | 現状 | 一般向けでの扱い |
|---|---|---|
| ダッシュボード | 資産寿命、残高、税社保、資産活用の概要を表示 | 残す。ただし結論優先に再設計 |
| 安全性シミュレーション入力 | 基本情報、初期資産、生活費、収入、税社保、特別支出、シナリオ | 残すが、標準入力と詳細入力に分ける |
| 資産活用ビュー | タイムバケット、クイック試算、資産レビュー、入金力診断 | 残す。ただし一般向けに言葉と導線を整理 |
| 結果 | 月次、年次、資産推移、収支詳細 | 詳細結果として残す。初期表示では前面に出さない |
| 比較 | 複数シナリオの横比較と差分 | 残す。ただし結論、理由、詳細の順に再構成 |
| データ | JSON入出力、履歴、共有保存、復旧 | 作り直す。共有保存と実データ復旧は一般向けから外す |
| マニュアル | 本人専用MVP前提の説明 | 全面改稿する |

現行の通常タブは情報量が多く、初回ユーザーには入力順が分かりにくい。一般向け版では、初回ウィザードを別途作り、通常タブは試算後の調整場所にする。

## 5. 保存処理の棚卸し

現行の保存方式:

- Zustand persist により LocalStorage へ自動保存
- 保存キーは `retirement-life-simulator-v2`
- 履歴バックアップを最大5件保持
- JSONエクスポート
- JSONバックアップ作成
- JSONインポート
- CSV出力
- サンプル復元
- QNAP共有保存API `/api/plan`
- Chrome 5173 復旧JSON導線

一般向けで問題になる点:

- QNAP共有保存は家族内MVP専用であり、一般向けには不適切
- 「このPCと奥様のPC」など個人利用前提の文言が残っている
- `実データを復旧` は一般公開版に出してはいけない
- LocalStorage の保存キーが現行版と同じで、同一ブラウザでデータが混ざる可能性がある
- サンプル復元の文言が、実データ復旧前提になっている

一般向け版での初期方針:

- 保存キーを一般向け版専用に変更する
- `/api/plan` 共有保存は通常導線から外す
- `実データを復旧` 導線を削除する
- JSON入出力は残す
- LocalStorage保存の説明を一般向けに書き換える
- 将来のクラウド保存は別フェーズにする

## 6. サンプルデータの棚卸し

現行サンプル:

- 1966年生まれの本人
- 東京都大田区
- 本人中心の世帯モデル
- 現状ケース
- 月10万円追加入金
- 生活費10%削減
- 特別支出発生
- 利回り0%
- 一般口座オプション用資産
- CFD
- 米国株オプション

一般向けで問題になる点:

- 自治体が大田区に固定されている
- 一般口座オプション、CFD、米国株オプションが初期状態から強く出ている
- 単身・本人中心の前提が強い
- 一般ユーザーには投資前提が濃く見える

一般向け初期サンプルの方針:

- 匿名の標準世帯サンプルを別途作る
- 単身サンプルと夫婦サンプルを分ける
- 一般口座オプションは詳細サンプルに下げる
- 初期シナリオは、現状、生活費抑制、受給開始変更、楽しみ支出追加などにする

## 9. リスク

| リスク | 内容 | 対応 |
|---|---|---|
| UI肥大化 | `App.tsx` が巨大で、画面改修の影響範囲が広い | 一般向け版で段階的にコンポーネント分割する |
| 保存混在 | LocalStorageキーが現行版と同じ | 早期に専用キーへ変更する |
| 個人前提混入 | 復旧、QNAP、奥様PCなどの文言が残る | Phase 3 で削除対象を先に処理する |
| 入力過多 | 初回から詳細入力が多すぎる | Phase 2 で標準入力を固定してから実装する |
| 税社保誤解 | 概算なのに正確な通知額のように見える | Phase 6 と Phase 9 で対応年度・免責・根拠表示を入れる |
| 投資色の強さ | オプションやCFDが初期表示に残る | 初期サンプルと初期UIから外し、詳細モードへ下げる |

## 10. Phase 1 の判断

一般向け版では、計算エンジンは最大限流用する。

一方で、UI、保存、初期サンプル、説明文は大きく作り直す。

最初に直すべき技術的分離は、保存キー、共有保存導線、実データ復旧導線である。

最初に直すべき体験上の分離は、初回ウィザード、税社保要約、一般向けサンプルである。
