# 一般向け版 移行方針

作成日: 2026-05-19

対象アプリ: `apps/retirement-life-planner-public`

## 1. 基本方針

現行版をそのまま公開可能な形へ薄く修正するのではなく、計算エンジンを活かして、一般向けの入力体験と結果表示を作り直す。

移行判断は次の3分類で行う。

- `流用`: 計算ロジックや型は原則そのまま使う
- `再設計`: 機能は残すが、画面、言葉、導線を作り直す
- `除外`: 一般向け初期版から外す

## 2. 流用するもの

### 2.1 計算ロジック

次の計算ロジックは一般向け版でも中核として流用する。

- `src/lib/simulation.ts`
- `src/lib/taxEngine.ts`
- `src/lib/retirementIncome.ts`
- `src/lib/pensionPlanner.ts`
- `src/lib/flexibleFreeCash.ts`
- `src/lib/assetUseAnalysis.ts`
- `src/lib/scenarioDiff.ts`
- `src/lib/taxFilingAdvice.ts`

理由:

- 税社保込みの使えるお金がアプリの差別化要素である
- 既に回帰テストが存在する
- 現行版で本人利用に耐える実用性がある

注意:

- 計算根拠の表示は一般向けに再整理する
- 自治体差や制度年度は免責と対応年度を明示する
- 一般向け初期画面で詳細な計算表をむき出しにしない

### 2.2 型定義

`src/types.ts` は当面流用する。

理由:

- 世帯、資産、収入、税社保、シナリオの型が既に揃っている
- 初回ウィザードも最終的には同じ `ScenarioData` へ変換できる

注意:

- 標準入力用の薄い入力モデルを別に作る可能性がある
- UI用の入力途中状態は `ScenarioData` に直接入れず、変換層を挟む方が安全

### 2.3 テスト資産

既存テストは流用する。

理由:

- 一般向けUIを作り直しても、計算結果の安全性を担保できる
- 税社保、資産推移、シナリオ差分の回帰確認に使える

追加するテスト:

- 一般向け保存キー
- 初回ウィザードからのシナリオ生成
- 個人向け導線の非表示
- 匿名サンプルの検証

## 3. 再設計するもの

### 3.1 `src/App.tsx`

現行の `App.tsx` は巨大で、画面、保存、説明、データ入出力が密結合している。

一般向け版では、段階的に次へ分割する。

- `features/onboarding`
- `features/dashboard`
- `features/inputs`
- `features/tax-social`
- `features/scenarios`
- `features/asset-use`
- `features/data-management`
- `features/help`

初期段階では大きな全面分割より、まずリスクの高い保存・復旧・共有導線を分離する。

### 3.2 初回入力

現行は詳細入力タブから始まる。

一般向け版では初回ウィザードを追加する。

ウィザード:

1. 家族
2. 資産
3. 収入
4. 支出
5. やりたいこと
6. 結果

ウィザードは標準入力を中心にする。

年齢別生活費変更、インフレ率、資産別利回りは標準入力に含める。ただし、初回から細かい表を出すのではなく、代表パターンや標準値を選ぶ形にする。

詳細入力と専門補正は初回から入力欄を並べない。ただし、ウィザード内で「詳しく設定する / 今は標準前提で進む」を確認し、該当者が後から見つけられる導線を置く。

### 3.3 ダッシュボード

現行のダッシュボードは多くの情報を出している。

一般向け版では次を前面に出す。

- 資産寿命
- 指定年齢時点残高
- 税社保後の使えるお金
- 税社保が重い年
- 翌年負担に注意する年
- 健康寿命期の楽しみ支出余地

### 3.4 税金・社会保険タブ

税社保計算は残す。

ただし、初期表示は詳細表ではなく要約にする。

表示順:

1. 年ごとの税社保負担
2. 負担が増える年
3. 増えた原因
4. 使えるお金への影響
5. 詳細内訳
6. 計算根拠

### 3.5 シナリオ比較

現行の比較は情報量が多い。

一般向け版では次の順にする。

1. 結論
2. なぜそうなったか
3. 税社保と手取りへの影響
4. 資産寿命と残高への影響
5. 詳細表

### 3.6 タイムバケット

現行のタイムバケットは有効だが、本人利用の前提が強い。

一般向け版では次を追加する。

- やりたいことテンプレート
- 金額未定の仮置き
- 夫婦それぞれの希望
- 健康寿命期との接続
- 特別支出化するかどうかの補助

### 3.7 マニュアルとヘルプ

現行のマニュアルは本人専用MVPの説明が残っている。

一般向け版では次へ置き換える。

- このアプリで分かること
- 最初に入力すること
- 税社保計算の考え方
- 概算と免責
- 保存先と削除方法
- 専門家に確認すべき場面

## 4. 除外するもの

一般向け初期版から外すもの:

- QNAP共有保存API `/api/plan`
- `共有保存へ保存` ボタン
- `このPCと奥様のPC` 文言
- `実データを復旧` ボタン
- Chrome 5173 復旧JSON導線
- 本人専用MVPの説明
- 個人利用前提の導線

初期表示から外して詳細モードへ下げるもの:

- 一般口座オプションを中心にした説明
- CFD、米国株オプションの具体サンプル
- 入金力診断
- オプションサブ口座
- 税扶養、国保月数、後期高齢者医療の詳細判定

## 5. 優先実装順

### Step 1: 技術的な混在防止

- LocalStorageキーを一般向け専用に変更する
- QNAP共有保存導線を外す
- 実データ復旧導線を外す
- データ画面の文言を一般向けにする

理由:

一般向け版の作業中に現行版データと混ざるのを避けるため。

### Step 2: 匿名サンプル化

- 初期サンプルを一般向け匿名サンプルに置き換える
- CFD、米国株オプションを初期サンプルから外す
- 単身サンプル、夫婦サンプルを定義する
- サンプル名を一般ユーザー向けにする

理由:

一般向け版の入口で、特定の個人利用や投資手法に見えないようにするため。

### Step 3: 初回ウィザード

- 標準入力だけで試算できる導線を作る
- 詳細入力は後から開く構造にする

理由:

現行UIの入力密度をそのまま出すと離脱しやすいため。

### Step 4: 税社保要約

- ダッシュボードと税社保タブに要約を作る
- 注意年、原因、使えるお金への影響を表示する

理由:

税社保込みの使えるお金がアプリの価値の中心であるため。

### Step 5: 比較とタイムバケット

- シナリオ比較を結論先行にする
- タイムバケットを一般向けテンプレート化する

理由:

初回試算後に、ユーザーが具体的な行動判断へ進むため。

## 6. 当面の実装判断

今すぐ UI 全体の大規模分割には入らない。

先に、一般向け版として危険なものを外す。

最初の実装対象は次にする。

1. 保存キーを `retirement-life-planner-public-v1` へ変更
2. QNAP共有保存の自動読み込みと保存ボタンを無効化
3. 実データ復旧導線を削除
4. データ画面の説明を一般向けに変更
5. マニュアルの本人専用MVP文言を削除

これにより、一般向け版の作業を進めても現行版データと混ざりにくくなる。

## 7. 完了判定

Phase 1 の完了条件:

- 現行版から流用するコード領域が明確である
- 作り直すUI領域が明確である
- 一般向け版に残してはいけない個人前提が一覧化されている
- 次の実装順が明確である
