# 一般向け版 データモデル・保存方針

作成日: 2026-05-19

対象アプリ: `apps/retirement-life-planner-public`

## 1. 基本方針

一般向け版では、現行の本人・夫婦向け版と保存データを混在させない。

初期段階ではクラウド保存やユーザー認証を入れず、ブラウザ内保存とJSON入出力を基本にする。

将来の一般公開や家族共有に備えて、クラウド保存は別フェーズで設計する。

## 2. 保存方式

### 2.1 初期版

初期版の保存方式:

- ブラウザ内 LocalStorage 自動保存
- 履歴バックアップ
- JSONエクスポート
- JSONインポート
- CSV出力
- サンプルに戻す

初期版で使わない保存方式:

- QNAP共有保存API
- 家族内共有保存
- ユーザー認証
- クラウド保存
- 複数端末同期
- 同時編集

### 2.2 LocalStorage キー

現行版の保存キー:

```text
retirement-life-simulator-v2
```

一般向け版の保存キー:

```text
retirement-life-planner-public-v1
```

理由:

- 現行の本人・夫婦向け版と保存データを混ぜない
- 一般向け版のサンプルや入力途中データが現行版に影響しない
- 将来、一般向け版のデータ構造を変える余地を残す

## 3. 一般向け版から外す導線

### 3.1 QNAP共有保存

外すもの:

- 起動時の `GET /api/plan`
- 自動保存時の `PUT /api/plan`
- `共有保存へ保存` ボタン
- `共有保存` ステータス表示
- `このPCと奥様のPC` 文言
- `QNAP` 文言

理由:

- 家族内MVP専用の保存方式である
- 一般向けユーザーには意味が分からない
- 認証、権限、競合解決、削除権がない

### 3.2 実データ復旧

外すもの:

- `restore=chrome5173` クエリによる復旧
- `/recovered_retirement_5173_from_chrome.json` の読み込み
- `実データを復旧` ボタン
- `Chrome 5173` 文言
- サンプル復元後に実データ復旧を促す注意文

理由:

- 個人用復旧導線であり、一般公開版に出してはいけない
- ユーザーにとって意味が分からない
- 実データ混入リスクがある

## 4. 残す導線

一般向け初期版で残すもの:

- 自動保存
- 最終保存時刻
- JSONエクスポート
- JSONバックアップ作成
- JSONインポート
- 履歴に保存
- 履歴から復元
- 履歴削除
- サンプルに戻す
- 月次CSV出力

文言方針:

- `LocalStorage` という技術名は詳細説明に回す
- 初期表示では「このブラウザ内に自動保存」と説明する
- 別ブラウザ、別端末には自動で同期されないことを説明する
- JSONバックアップで手元に保存できることを説明する

## 5. データ削除とリセット

一般向け版には、次の操作を用意する。

- サンプルに戻す
- ブラウザ内データを削除する
- JSONバックアップを作成してから削除する

初期実装では、少なくとも `サンプルに戻す` を残し、文言を一般向けに変更する。

将来の正式公開では、明示的な `このブラウザの保存データを削除` を追加する。

## 6. データモデル

### 6.1 当面の方針

当面は既存の `RetirementPlanState` と `ScenarioData` を流用する。

理由:

- 既存計算エンジンとテスト資産を活かせる
- 初回ウィザードも最終的には `ScenarioData` へ変換できる
- 一般向け版の初期段階で型を全面変更するとリスクが高い

### 6.2 追加する可能性があるUI用モデル

初回ウィザードでは、直接 `ScenarioData` を編集しない方がよい。

候補:

```text
OnboardingDraft
```

役割:

- 初回ウィザードの入力途中状態を保持する
- 必須項目の入力チェックを行う
- 標準入力だけを扱う
- 完了時に `ScenarioData` へ変換する

この設計にすると、詳細入力や専門補正を開かずに試算できる。

## 7. 匿名サンプルデータ

一般向け版の初期サンプルは `sample-households.md` の方針に従う。

初期サンプルの候補:

- 退職前夫婦世帯
- 退職直後単身世帯

初期表示に使わないサンプル:

- 詳細投資あり世帯
- 一般口座オプション中心のケース
- CFD
- 米国株オプション

実装方針:

- 現行の `sampleState` を一般向け匿名サンプルへ置き換える
- 詳細投資ありサンプルはテスト用または詳細モード用に分離する
- シナリオ名を一般向けに変える

初期シナリオ案:

1. 標準ケース
2. 生活費を少し抑える
3. 年金受給を遅らせる
4. 健康寿命期に楽しみ支出を追加する
5. 利回りを低めに見る

## 8. JSON入出力

JSON入出力は残す。

ただし、次を明示する。

- JSONには入力した家計・資産情報が含まれる
- 共有や送付には注意が必要
- インポートすると現在の入力内容が置き換わる
- インポート前には履歴バックアップを残す

一般向け版では、JSONファイル名も変更する。

現行:

```text
retirement-simulation.json
```

一般向け候補:

```text
retirement-life-plan-public.json
```

または:

```text
retirement-life-plan-backup.json
```

## 9. Phase 3 から Phase 4 への実装順

最初の実装順:

1. LocalStorageキーを `retirement-life-planner-public-v1` に変更する
2. 起動時の `/api/plan` 読み込みを外す
3. `/api/plan` への保存処理を外す
4. 共有保存ステータスとボタンを削除する
5. `restore=chrome5173` 復旧処理を削除する
6. `実データを復旧` ボタンを削除する
7. データ画面の文言を一般向けに変更する
8. JSONファイル名を一般向けに変更する
9. 匿名サンプルデータへ置き換える

この順番で進める理由:

- 先に保存混在と実データ混入リスクを潰す
- その後で初回ウィザードやダッシュボードを作る
- UIを作り始めた後に保存導線を直すと、確認範囲が広がりすぎる
