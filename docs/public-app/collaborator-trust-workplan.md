# 協力者向け安心説明 実装工程表

作成日: 2026-05-21
実装状況: 2026-05-21 実装済み

目的: GitHub Pagesを知らない協力者でも、入力データが作成者側へ送信されない設計であることを理解し、安心して試用できる状態にする。

重要な表現方針:

- 「絶対に渡らない」と断定しない。
- 「このアプリには、入力内容を作成者へ送信する機能がない」と説明する。
- 「自分で保存用ファイル、画面の画像、入力内容を送った場合は送付先に伝わる」と明示する。
- GitHub Pagesは「アプリ本体を置いている場所」、ご利用中の端末は「入力・計算・保存をする場所」と分けて説明する。

## Phase A: 説明設計

目的: 協力者に見せる説明文と図を確定する。

作業:

- データの流れを3段階で図示する。
- 「送られるもの」と「送られないもの」を分けて書く。
- GitHub Pagesという言葉を知らなくても分かるように言い換える。
- 保存用ファイル、画面の画像、フィードバック送付時の注意を短く書く。

成果物:

- `docs/public-app/collaborator-instructions.md`
- アプリ内表示文案
- 簡易データフロー図

完了条件:

- 協力者へそのまま送れる説明文がある。
- 「アプリ本体」と「入力データ」の違いが説明されている。
- 送付してはいけない情報が明記されている。

実装結果:

- `docs/public-app/collaborator-instructions.md` を作成。
- `docs/public-app/collaborator-feedback-request.md` を作成。
- `docs/public-app/collaborator-feedback-questions.md` を作成。

## Phase B: 初回表示の安心説明モーダル

目的: 協力者が使い始める前に、データ保存場所を確認できるようにする。

作業:

- 初回アクセス時に「データの扱い」モーダルを表示する。
- 表示内容は以下にする。
  - 限定公開版であること
  - 計算は概算であること
  - 入力内容は本人が使っている端末内に保存されること
  - 作成者へ入力内容を送信する機能はないこと
  - 保存用ファイルや画面の画像を自分で送る場合は内容が伝わること
- 「確認しました（次回から表示しない）」ボタンで閉じる。
- 一度閉じた後も、ヘッダーまたはマニュアルから再表示できる導線を用意する。

成果物:

- 初回説明モーダル
- 再表示ボタンまたはマニュアル内リンク

完了条件:

- 初回表示で必ず確認できる。
- 閉じた後も再確認できる。
- スマートフォン幅でも読み切れる。

実装結果:

- 初回表示の「データの扱い」モーダルを追加。
- ヘッダーに「データの扱い」再表示ボタンを追加。
- 通常操作では入力内容を作成者へ送信しないこと、保存用ファイルや画像を送った場合だけ共有されることを説明。

## Phase C: マニュアルへの図入り説明追加

目的: 後から確認したい協力者向けに、データの流れを視覚的に説明する。

作業:

- マニュアルに「データはどこに保存されるか」を追加する。
- 図は次の構造にする。

```text
アプリ置き場
アプリ本体だけを配る
        ↓
ご利用中の端末
入力・計算・保存を行う
        ↓
あなたの端末内の保存領域
入力データが保存される
```

- 「作成者へ送られないもの」を別枠で表示する。
- 「自分で送った場合だけ伝わるもの」を別枠で表示する。

成果物:

- マニュアル内の図入り説明

完了条件:

- GitHub Pagesを知らなくても読める。
- 入力データとアプリ本体が混同されない。

実装結果:

- マニュアルの「プライバシーとフィードバック」に、アプリ置き場、ご利用中の端末、配布者・作成者の3項目説明を追加。
- 共有されるものとされないもの、削除方法の説明を追加。

## Phase D: データタブの安全導線強化

目的: 入力データの削除とバックアップの扱いを分かりやすくする。

作業:

- データタブに「この端末から入力データを削除」導線を明確に表示する。
- 保存用ファイル出力前に「このファイルには家計・資産情報が含まれます」と確認する。
- 保存用ファイル読込にも「読み込むとこの端末の保存内容が置き換わる」注意を表示する。
- フィードバック時に保存用ファイルを送らない案内を追加する。

成果物:

- データ削除説明
- 保存用ファイル出力確認
- 保存用ファイル読込注意

完了条件:

- 協力者が自分で保存データを消せることを理解できる。
- 保存用ファイルを不用意に送らない注意が画面上にある。

実装結果:

- データタブへ保存場所、保存用ファイル注意、端末内データ削除ボタンを追加。
- 保存用ファイル出力、保存用バックアップ、保存用ファイル読込前に確認ダイアログを表示。
- 端末内の入力データと履歴バックアップを初期サンプルへ戻す削除処理を追加。

## Phase E: フィードバック依頼文の作成

目的: 協力者へ送る文章をそのまま使える状態にする。

作業:

- 協力者へ送る案内文を作る。
- フィードバックで答えてほしい項目を作る。
- 書かなくてよい情報、送らないでほしい情報を明記する。
- Googleフォームまたはメールに貼り付けられる形にする。

成果物:

- `docs/public-app/collaborator-feedback-request.md`
- `docs/public-app/collaborator-feedback-questions.md`

完了条件:

- 協力者へURLと一緒に送れる。
- 個人情報や実額を要求しない設計になっている。

実装結果:

- 依頼文と質問票を作成済み。
- フィードバックでは実額・保存用ファイル・個人情報を求めない方針を明記。

## Phase F: QA

目的: 安心説明が実際に読め、誤解を生みにくいことを確認する。

作業:

- `npm run test:public`
- `npm run build:public`
- 初回表示モーダルの表示確認
- モーダル再表示導線の確認
- マニュアルの図入り説明確認
- データタブの削除・保存用ファイル注意文確認
- スマートフォン幅で表示確認
- 「普通口座」など既知の旧文言が残っていないか検索

成果物:

- `docs/public-app/qa-collaborator-trust-2026-05-21.md`

完了条件:

- テストとビルドが成功する。
- PC幅とスマートフォン幅で説明が読める。
- 協力者に渡す前の重大な不安要素が残っていない。

## 実施順序

1. Phase A: 説明設計
2. Phase B: 初回表示モーダル
3. Phase C: マニュアル説明
4. Phase D: データタブ安全導線
5. Phase E: フィードバック依頼文
6. Phase F: QA

## 想定完了後の状態

協力者には、次の3点を明確に伝えたうえでURLを渡せる。

- アプリ本体はWebから読み込む。
- 入力データは本人が使っている端末内に保存される。
- 作成者へ入力内容を送る機能はない。ただし、自分で保存用ファイルや画面の画像を送れば、その内容は送付先に伝わる。
