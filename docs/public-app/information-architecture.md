### Step 0: 目的

目的: 退職済みユーザーだけでなく、現役会社員が何を知りたいかを最初に決める。

入力:

- 現在の状態: 退職前 / 退職済み / 退職後も働く / 年金生活中
- 今回知りたいこと
  - 何歳時点でいくら資産ができるか
  - 早期リタイアできる年齢
  - 仕事を減らす、セカンドビジネスを始める前提
  - 教育費、住宅ローン、親の介護を含めた試算
  - 家族旅行、趣味、学びなどに使える金額
  - 年金、iDeCo、退職金の受け取り方

目的選択に応じて、入力状況サマリー、ダッシュボード、初回表示カードの優先順位を切り替える。

### Step 1: 家族

目的: 世帯と年齢の前提を決める。

入力:

- 本人の生年月日または現在年齢
- 配偶者の有無
- 配偶者の生年月日または現在年齢
- 退職済みまたは退職予定
- シミュレーション開始年月
- 何歳まで見るか
- 何歳時点でいくら残したいか

詳細確認:

- 扶養家族を詳しく設定するか
- 国民健康保険、後期高齢者医療、介護保険を詳しく設定するか

### Step 2: 資産

目的: 現在の資産と負債を大まかに把握する。

入力:

- 現金・預金
- NISA
- iDeCo
- 課税口座
- その他運用資産
- その他資産
- 負債

詳細確認:

- 課税口座の取得原価を詳しく入れるか
- 源泉あり・源泉なしを詳しく設定するか
- 一般口座オプション等の申告対象損益を扱うか

### Step 3: 収入・働き方

目的: 現在の収入、今後の働き方、退職後の主な収入を把握する。

入力:

- 現在の給与、賞与、事業収入
- 何歳まで今の働き方を続けるか
- 仕事を減らす予定、セカンドビジネス予定
- 年金見込み額
- 年金受給開始年齢
- 給与、パート、事業などの予定収入
- iDeCo受取予定
- 退職金または一時金の有無

詳細確認:

- iDeCo一時金、退職金、過去の退職所得を詳しく設定するか
- 世帯メンバー別の収入を詳しく分けるか

iDeCo受取の表示:

- iDeCoを原資資産として選んだ場合、汎用的な「種別」ではなく「iDeCo受取方法」と表示する。
- 選択肢は「iDeCo年金受取（雑所得）」と「iDeCo一時金（一括受取・退職所得）」に絞る。
- iDeCo一時金では、加入年数に加えて、加入開始日・加入終了日を任意入力として出す。
- 加入開始日・加入終了日は、過去退職金との退職所得控除重複調整を日付ベースで概算したい利用者向けの詳細入力とする。

### Step 4: 支出

目的: 毎月の生活費と将来変化を把握する。

入力:

- 毎月の生活費
- 住宅費
- 医療・介護費
- 大きな予定支出
- 年齢別生活費変更

標準パターン:

- 変えない
- 70歳以降に生活費を少し下げる
- 75歳以降に医療・介護費を増やす
- 自分で設定する

### Step 5: ライフイベント

目的: 教育費、住宅ローン、親の介護など、資産形成と早期リタイア判断に影響する大きな支出を見落とさない。

テンプレート:

- 教育費
- 住宅ローン・住まい
- 親の介護・支援
- 車
- 子どもの独立・結婚支援
- 転職・独立・セカンドビジネス準備

P0では、教育費、住宅ローン・住まい、親の介護・支援、家族旅行・体験を優先する。

反映先:

- 特別支出
- 年齢別生活費変更
- 収入イベント
- 負債入力

### Step 6: 前提調整

目的: 結果に効く標準前提を確認する。

入力:

- インフレ率
- 資産別利回り
- 税社保の計算方法

標準パターン:

- インフレ率: 標準値を使う / 低め / 高め / 自分で設定する
- 資産別利回り: 低め / 標準 / 高め / 個別入力
- 税社保: 自動概算 / 自動概算 + 後で補正 / 詳しく設定する

### Step 7: やりたいこと

目的: 健康寿命期に使いたいお金を仮置きする。

入力:

- 旅行
- 趣味
- 家族イベント
- 学び・体験
- 住まい
- 医療・介護
- その他

金額未定でも登録できる。

教育費、住宅ローン、親の介護などの生活・責任支出とは分け、旅行、趣味、学び、家族イベントなどの体験・楽しみ支出を主に扱う。

### Step 8: 結果

目的: 最初の試算結果を見せ、次に調整すべき項目を案内する。

表示:

- 資産寿命
- 指定年齢時点残高
- 税社保後の使えるお金
- 税社保が重い年
- 健康寿命期の楽しみ支出余地
- 詳細設定が未完了の項目

退職前ユーザーには、資産寿命だけでなく次も優先表示する。

- 60歳時点の見込み資産
- 65歳時点の見込み資産
- 仕事をやめても成立しそうな年齢
- ライフイベント支出が重なる注意年
- 健康なうちに楽しみに使える年額

## 表示方針

- 最初に結論を見せる
- 次に理由を見せる
- 詳細表は必要な人だけ開ける
- 税金・社会保険タブは隠さない
- 専門用語はやさしい表示名を先に出し、詳細モードで正式名称を併記する
- 詳細入力と専門補正は初回から入力欄を並べず、ウィザードで「詳しく設定する / 今は標準前提で進む」を選べるようにする
- 詳細入力と専門補正は、初回完了後もダッシュボード、入力画面、重要前提サマリーからいつでも開けるようにする
- iDeCo一時金のように、選択肢名を間違えると税区分が変わる項目は、汎用カテゴリ名よりも税務上の意味が分かる専用名を優先する。

## 通常入力画面の誘導方針

詳細設計:

- `ux-guided-input-card-collapse-design.md`

通常入力画面は、単にすべての入力欄を並べる場所ではなく、ユーザーが次に何を入力・確認すればよいかを案内する場所にする。

共通ルール:

- 各入力タブの上部に入力状況サマリーを置く。
- 必須、推奨、詳細、専門補正をカード単位で区別する。
- カードの表示状態を、常時表示、要約表示、折りたたみ、非表示に分ける。
- 各入力タブで、初期状態でフル表示するカードは原則1カードにする。
- 入力状況サマリーと次に入力すべきカードを除き、PC画面を覆うほど複数カードを全体表示しない。
- 未完了の必須カード、結果から指定されたカード、確認推奨カードだけを初期展開する。
- 完了済みカードは要約だけ表示し、必要な時に開ける。
- 計算に使っていないカードは全入力欄を見せず、`計算対象外` などの要約表示にする。
- 入力完了後は、勝手に画面移動せず、`次へ` ボタンで次のカードへ進める。
- 入力完了後、次に必要なカードを枠色、ラベル、タブバッジで促す。
- `6/6` のような進捗表記だけでなく、`6項目中6項目完了` のように意味を明示する。
- 必須入力が完了していて推奨項目が残る場合は、`次に入力` ではなく `次に確認するとよい` と表示する。
- 入力状況サマリーの次対象枠はクリック可能にし、対象タブ、対象カード、最初に必要な入力欄へ移動する。
- `ダッシュボード` と `結果` からも、入力状況サマリーまたは次対象へアクセスできるようにする。
- 結果画面やダッシュボードの注意表示から、該当する入力カードや根拠カードへ戻れるようにする。

推奨入力順:

1. 家族・期間
2. 現在資産
3. 生活費
4. 年金・給与・iDeCo・退職金
5. 税金・社会保険の計算方法
6. 特別支出・やりたいこと
7. 結果確認

初期資産タブの優先順位:

- `現在資産` の次に確認させる対象は、`NISA・iDeCo・特定口座などの評価額と評価損益` とする。
- `一般口座（申告対象運用）のサブ口座` は詳細・専門寄りのカードとして扱い、通常の初期表示では畳む。
- `証券・iDeCoの評価額と評価損益` という文言は、NISAが主対象であることが伝わりにくいため使わない。
- 表示名は `NISA・iDeCo・特定口座などの評価額と評価損益` とする。
- この方針は一般向け版だけでなく、ローカル版にも同じく適用する。
