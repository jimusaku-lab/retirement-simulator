# シナリオ反映における一般口座サブ口座と収入イベントの連動設計

作成日: 2026-06-12

対象:

- ローカル版: `apps/retirement-life-planner`
- 公開版: `apps/retirement-life-planner-public`
- ベータ版: `apps/life-asset-simulator-beta`

## 背景

シナリオ間で前提をコピーする機能では、現在、入力タブごとに反映操作が分かれている。

- 収入タブ: 収入イベント、年金プランナー、退職所得イベント、年金改定率
- 初期資産タブ: 現金・預金、NISA・iDeCo・特定口座、取得原価、一般口座サブ口座

しかし、一般口座オプション用の収入イベントは、単独では意味が完結しない。

例:

- `CFD` 収入イベント
- `米国株オプション` 収入イベント

これらは `sourceAssetKey = ordinaryAccountForOptions` を持ち、一般口座サブ口座の評価額、取得原価、最低維持証拠金、保護設定などを前提として計算される。

そのため、収入イベントだけを他シナリオへ反映しても、反映先の初期資産側に該当サブ口座がなければ、ユーザーの意図した前提にならない。

逆に、初期資産タブから一般口座サブ口座だけを反映しても、関連する収入イベントがなければ、入金力・収益シナリオとしては成立しない。

## 問題

ユーザー観点の問題:

- `収入イベント` と `一般口座サブ口座` が別タブにあるため、関連していることが見えにくい。
- 収入イベントだけコピーした時、初期資産側のサブ口座が空のままでも、画面上はコピーが成功したように見える。
- 初期資産側の `他シナリオへ反映` を別途実行すれば整合するが、ユーザーに二重操作を要求している。
- どちらを先にコピーすべきか、何を一緒にコピーすべきかがユーザー判断に委ねられている。

設計上の問題:

- シナリオ反映が「タブ単位」になっており、「依存関係単位」になっていない。
- `ordinaryAccountForOptions` 由来の収入イベントを検出できるにもかかわらず、関連サブ口座のコピー提案がない。
- 一般口座サブ口座をコピーする時に、関連収入イベントのコピー提案がない。

## 設計方針

シナリオ反映では、ユーザーが選んだ主対象に対して、計算上必要な関連前提をアプリ側が検出し、同時反映を提案する。

重要な方針:

- 自動で黙ってコピーしない。
- ただし、関連前提がある場合は `一緒に反映する（推奨）` を初期ONにする。
- ユーザーが明示的にOFFにできる。
- OFFにした場合は、計算前提が不完全になる可能性を警告する。
- 反映前の確認ダイアログに、主対象と関連対象の件数・名称を出す。
- 反映後メッセージにも、何をコピーしたかを出す。

## 収入タブ側の設計

### 対象検出

収入タブの `コピーする収入イベント` で選択されたイベントのうち、以下を関連判定対象とする。

- `event.sourceAssetKey === "ordinaryAccountForOptions"`

関連サブ口座の特定:

1. `event.sourceOptionSubAccountId` があり、コピー元シナリオの `optionSubAccounts` に存在する場合はそれを使う。
2. IDが未設定または見つからない場合は、イベント名、サブ口座名、シナリオ名から既存の推定ロジックで候補を探す。
3. 推定できない場合は、`関連サブ口座未特定` として警告する。

### UI

収入タブのシナリオ反映カード内に、選択中の収入イベントから関連サブ口座を検出した時だけ、以下の関連前提パネルを表示する。

表示例:

```text
関連する初期資産があります
選択した収入イベントは、一般口座サブ口座を原資にしています。

[x] 関連する一般口座サブ口座の初期条件も一緒に反映する（推奨）

対象:
- CFD: 評価額 200万円 / 取得原価 170万円 / 最低維持証拠金 100万円
- 米国株オプション: 評価額 200万円 / 取得原価 150万円 / 最低維持証拠金 150万円
```

OFFにした場合の警告:

```text
収入イベントだけを反映すると、反映先シナリオの一般口座サブ口座が未設定または古いままになる可能性があります。
```

### 反映するデータ

ONの場合、選択された収入イベントに紐づくサブ口座について、以下を反映する。

- `optionSubAccounts` の該当サブ口座
- `optionAccountRules`
- `initialAssets.ordinaryAccountForOptions`
- `initialAssetCostBasis.ordinaryAccountForOptions`
- `assetGrowthSettings.rates.ordinaryAccountForOptions`

`initialAssets.ordinaryAccountForOptions` と `initialAssetCostBasis.ordinaryAccountForOptions` は、反映後の `optionSubAccounts` の合計から再計算する。

反映先にだけ存在する別サブ口座は削除しない。

## 初期資産タブ側の設計

### 対象検出

初期資産タブで `一般口座サブ口座` を反映対象にした時、コピー元シナリオ内の収入イベントから以下を検出する。

- `event.sourceAssetKey === "ordinaryAccountForOptions"`
- `event.sourceOptionSubAccountId` が、選択されたサブ口座IDに一致する

IDがない場合は、イベント名・サブ口座名・シナリオ名から推定する。

### UI

一般口座サブ口座をコピー対象に選んだ時だけ、関連収入イベントのパネルを表示する。

表示例:

```text
関連する収入イベントがあります
この一般口座サブ口座を原資にする収入イベントがあります。

[x] 関連する収入イベントも一緒に反映する（推奨）

対象:
- CFD収入: 月額 2万円 / 口座内積上
- 米国株オプション収入: 月額 10万円 / 口座内積上
```

OFFにした場合の警告:

```text
サブ口座だけを反映すると、反映先シナリオで収入イベントが作られず、入金力シナリオとしては成立しない可能性があります。
```

## 反映時の重複回避

関連収入イベントをコピーする場合、以下のいずれかが一致する既存イベントは置き換え対象とする。

- 同一 `id`
- `name`, `type`, `sourceAssetKey`, `sourceOptionSubAccountId` が一致

関連サブ口座をコピーする場合、以下のいずれかが一致する既存サブ口座は置き換え対象とする。

- 同一 `id`
- 同一 `name`

反映先にだけ存在する収入イベントやサブ口座は残す。

## 確認ダイアログ

反映前の確認ダイアログでは、以下を必ず表示する。

- コピー元シナリオ
- 反映先シナリオ
- 主対象
- 関連対象
- OFFにした関連対象がある場合の注意

表示例:

```text
「米国株オプション10」から、以下を3件のシナリオへ反映します。

主対象:
- 収入イベント 2件

関連対象:
- 一般口座サブ口座 2件（CFD、米国株オプション）

実行しますか？
```

## 完了条件

- 収入タブで一般口座サブ口座由来の収入イベントを選ぶと、関連サブ口座の同時反映提案が出る。
- 同時反映をONにした場合、反映先の一般口座サブ口座、評価額、取得原価、ルール、利回りが整合する。
- 同時反映をOFFにした場合、警告が出る。
- 初期資産タブで一般口座サブ口座を反映対象にすると、関連収入イベントの同時反映提案が出る。
- 関連収入イベントをONにした場合、反映先に収入イベントが入り、サブ口座参照IDが正しく解決される。
- 反映先にだけある収入イベントやサブ口座は削除されない。
- ローカル版、公開版、ベータ版で同じ挙動になる。
- テストで、収入側からの関連サブ口座コピー、資産側からの関連収入イベントコピー、OFF時の非コピーが確認されている。
