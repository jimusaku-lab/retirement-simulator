# 入力項目分類

## 標準入力

- 本人の年齢または生年月日
- 配偶者の有無と年齢
- 退職予定または退職済み
- 年金見込み額
- iDeCo残高と受取予定
- 現金・預金
- NISA
- その他運用資産
- 毎月の生活費
- 年齢別生活費変更
- インフレ率
- 資産別利回り
- 大きな予定支出
- やりたいこと
- 何歳まで資産を残したいか
- その時点で残したい金額

標準入力に含めるが、初回ウィザードでは「使う / 今は使わない」を選べるようにする。

- 年齢別生活費変更: 退職直後、70歳以降、75歳以降などの代表パターンを用意する
- インフレ率: 標準値を先に入れ、必要な人だけ変更できるようにする
- 資産別利回り: 低め、標準、高め、個別入力を選べるようにする

## 詳細入力

- 世帯メンバー別の収入
- 扶養家族
- 国民健康保険の加入予定
- 後期高齢者医療への切替
- 介護保険
- 所得控除
- 退職所得履歴
- iDeCo年金受取とiDeCo一時金（一括受取）
- 特定口座の取得原価
- NISA・iDeCo・特定口座などの評価額と評価損益

## 専門補正

- 税扶養の年末判定
- 国保加入月
- 自治体別の国保・介護・後期高齢者医療補正
- 退職所得控除の重複ルール
- 源泉あり・源泉なし
- 一般口座オプションの申告対象損益
- 一般口座（申告対象運用）のサブ口座
- 実際の通知額による補正

## 初回ウィザードでの扱い

詳細入力と専門補正は、初回から入力欄を並べない。

ただし、ユーザーが該当する可能性を見落とさないよう、ウィザード内で短く確認する。

例:

- 税金や社会保険の通知額で補正したいですか
- 扶養、国保、後期高齢者医療などを細かく調整しますか
- iDeCo一時金、退職金、過去の退職所得を詳しく入れますか
- 課税口座の取得原価や源泉あり・なしを詳しく入れますか

回答が「今はしない」の場合:

- 標準前提で自動概算する
- ダッシュボードや入力画面から後で開ける
- 未設定であることを重要前提サマリーに表示する

回答が「詳しく設定する」の場合:

- 初回ウィザード内で詳細入力ステップを展開する
- または初回結果後に詳細入力タブへ案内する

したがって、詳細入力と専門補正は「最初は見せないが、いつでも開ける」扱いにする。

### iDeCo一時金の詳細項目

iDeCo残高があり、受取予定を詳しく設定する場合は、次の入力を使う。

| 項目 | 必須 | 用途 | 表示方針 |
|---|---:|---|---|
| iDeCo受取方法 | 必須 | 年金受取か一時金かを決める | `iDeCo年金受取（雑所得）` / `iDeCo一時金（一括受取・退職所得）` |
| 一時金受取額 | 一時金なら必須 | 受取月の入金額とiDeCo残高減少 | 金額入力 |
| 加入年数 | 一時金なら必須 | 退職所得控除額の年数 | 年数入力 |
| 加入開始日 | 任意 | 退職金との期間重複を日付で見る | 日付入力 |
| 加入終了日 | 任意 | 退職金との期間重複を日付で見る | 日付入力 |
| 退職所得の申告 | 一時金なら必須 | 退職所得控除で概算するか20.42%源泉で概算するか | 提出あり / 提出なし |

注意:

- 加入開始日・加入終了日を未入力にしても、加入年数は税額計算に使う。
- 日付未入力時は「年数ベースの概算」と明示する。
- 日付入力時は、退職所得履歴の勤続開始日・終了日と照合し「期間入力ベース」と表示する。
- iDeCo一時金は雑所得ではなく退職所得であり、国民健康保険・後期高齢者医療の所得割には含めない前提で説明する。

## 詳細導線

初回完了後、次の場所から詳細入力と専門補正を開けるようにする。

- ダッシュボードの重要前提サマリー
- 入力タブの詳細入力セクション
- 税金・社会保険タブの詳細設定
- データ画面の保存・復元ヘルプ
- 結果画面の注意メッセージ

表示例:

- 現在は税金・社会保険を標準前提で自動概算しています
- 課税口座の取得原価は未設定です
- 国民健康保険や後期高齢者医療の詳細条件は未設定です
- 実際の通知額が分かる場合は補正できます

## カード表示分類

通常入力画面では、入力項目の分類をカード表示にも反映する。

| 表示分類 | 目的 | 初期表示 |
|---|---|---|
| 必須 | 試算の前提として必要 | 未完了なら展開 |
| 推奨 | 精度や判断に効く | 条件付きで展開 |
| 詳細 | 分かる人だけ詳しく入力 | 折りたたみ |
| 専門補正 | 制度・通知書・申告に基づく補正 | 折りたたみ |

完了済みカードは、入力欄を常時表示せず、主要値と状態だけを要約表示する。

表示例:

- `完了: 現在資産 3,300万円`
- `要確認: iDeCo一時金の加入期間`
- `詳細未設定: 課税口座の取得原価`
- `任意: 税社保の通知書補正`

詳細設計は `ux-guided-input-card-collapse-design.md` に従う。

## カードの視線誘導

入力完了後は、次に必要なカードをユーザーが視覚的に見つけられるようにする。

表示ルール:

- 次に入力すべきカードには `次に入力` ラベルを出す。
- 同じ画面内にある場合は、カード枠をアンバー系で強調する。
- 別タブにある場合は、入力状況サマリーと対象タブに `次` 表示を出す。
- 不足があるカードは `不足あり` として赤系で表示する。
- 確認推奨は `確認推奨` として薄いアンバー系にする。
- 計算に使っていないカードは `計算対象外` としてグレー系の要約表示にする。
- 初期資産では、`NISA・iDeCo・特定口座などの評価額と評価損益` を確認推奨カードとして強調できるようにする。
- `一般口座（申告対象運用）のサブ口座` は専門寄りの詳細カードとして扱い、初期表示では畳む。

色だけで意味を伝えず、必ずラベルと要約文を併記する。

文言ルール:

- 必須未入力がある場合は `次に入力` と表示する。
- 必須入力が完了し、推奨項目だけが残る場合は `次に確認するとよい` と表示する。
- 専門項目は `必要なら確認` と表示する。
- 進捗は `6/6` だけで表示せず、`6項目中6項目完了` または `必須入力は完了` と表示する。
- 次対象のカードは表示だけでなくクリック可能にし、対象入力欄へ移動できるようにする。
