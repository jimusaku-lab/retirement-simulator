iDeCoを「一時金」で受け取る場合、税務上は退職所得として扱われる。会社退職金など、他の退職手当等と受取時期が近い場合、退職所得控除を二重に満額使うことはできず、退職所得控除の勤続期間・加入期間について重複調整が行われる。

## 2. 最重要結論

| 受取順序 | 税法上の主な表現 | 実務上の言い方 | シミュレーターでの扱い |
|---|---:|---:|---|
| iDeCo一時金を先に受け取り、会社退職金を後で受け取る | 2026年以後のDC老齢一時金は「前年以前9年内」 | 10年ルール | 原則10年以上空けないと警告 |
| 会社退職金を先に受け取り、iDeCo一時金を後で受け取る | iDeCo一時金受取年の「前年以前19年内」 | 20年ルール | 原則20年以上空けないと警告 |
| 同じ年に両方受け取る | 同一年の退職手当等として合算 | 同年受取は控除二重利用不可 | 同一年イベントとして合算 |

ここでいう「10年」「20年」は、税法条文上の言い方ではなく、利用者向けの実務表現である。コード上は「前年以前9年内」「前年以前19年内」として判定する。

## 3. iDeCo一時金の税務区分

iDeCoの老齢給付金を一時金で受け取る場合、税務上は退職所得である。

基本式:

```text
退職所得 = (退職手当等の収入金額 - 退職所得控除額) × 1/2
```

退職所得控除額:

```text
勤続年数等が20年以下:
  40万円 × 年数
  ただし80万円未満の場合は80万円

勤続年数等が20年超:
  800万円 + 70万円 × (年数 - 20年)
```

iDeCo一時金の場合は、会社の勤続年数ではなく、原則として確定拠出年金の加入者等期間を退職所得控除の年数として使う。

参照:
- 国税庁 No.1420 退職金を受け取ったとき（退職所得）
  https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1420.htm
- 国税庁 No.2725 退職所得となるもの
  https://www.nta.go.jp/taxes/shiraberu/taxanswer/gensen/2725.htm
- マネックス証券 iDeCo 大きな節税メリット
  https://info.monex.co.jp/ideco/knowledge/tax-saving.html

## 5. iDeCoを先に受け取り、会社退職金を後で受け取る場合

### 5.1 2025年以前によく言われた5年ルール

従来は、iDeCo一時金を先に受け取り、その後に会社退職金を受け取る場合、実務上「5年以上空ける」と説明されることが多かった。税法上は「前年以前4年内」という考え方である。

```text
iDeCo一時金: 2020年
会社退職金: 2025年

会社退職金の受取年2025年から見た前年以前4年:
2021年, 2022年, 2023年, 2024年

2020年のiDeCoは含まれない
→ 旧ルールでは重複調整対象外になりやすい
```

### 5.2 2026年以後は10年ルールに注意

令和7年度税制改正により、2026年1月1日以後に支払を受けた確定拠出年金の老齢一時金については、会社退職金など老齢一時金以外の退職手当等を後で受け取る場合、「前年以前9年内」の重複調整対象になる。

利用者向けには「10年以上空ける必要がある」と説明する。

```text
iDeCo一時金: 2026年
会社退職金: 2035年

2035年の前年以前9年:
2026年〜2034年

2026年のiDeCoが含まれる
→ 重複調整対象

iDeCo一時金: 2026年
会社退職金: 2036年

2036年の前年以前9年:
2027年〜2035年

2026年のiDeCoは含まれない
→ 原則として対象外
```

実装:

```ts
if (
  currentEvent.type !== "dc_lump_sum" &&
  priorEvent.isDcOldAgeLumpSum &&
  priorEvent.paymentDate >= "2026-01-01" &&
  currentEvent.year - priorEvent.year <= 9
) {
  overlapAdjustmentRequired = true;
  rule = "prior_dc_lump_sum_9_year_rule";
}
```

## 7. 4年・9年・19年ルールのまとめ

```text
通常の退職手当等:
  前年以前4年内に他の退職手当等がある場合は調整対象

2026年1月1日以後にiDeCo/DC老齢一時金を先に受けた場合:
  後で会社退職金などを受けるとき、前年以前9年内なら調整対象
```

## 9. Codex実装用判定関数

```ts
function getRetirementOverlapLookbackYears(
  currentEvent: RetirementEvent,
  priorEvent: RetirementEvent
): number | null {
  // 同一年はルックバックではなく同一年合算
  if (currentEvent.year === priorEvent.year) {
    return 0;
  }

  // 退職金を先に受け、後でiDeCo/DC老齢一時金を受ける場合
  // → 前年以前19年内
  if (currentEvent.isDcOldAgeLumpSum && priorEvent.isRetirementAllowance) {
    return 19;
  }

  // iDeCo/DC老齢一時金を先に受け、後で会社退職金などを受ける場合
  // 2026年1月1日以後に受けたDC老齢一時金は前年以前9年内
  if (
    !currentEvent.isDcOldAgeLumpSum &&
    priorEvent.isDcOldAgeLumpSum &&
    priorEvent.paymentDate >= "2026-01-01"
  ) {
    return 9;
  }

  // 通常の退職手当等、または2026年1月1日前のDC老齢一時金については
  // 従来の前年以前4年内を基本にする
  if (priorEvent.isRetirementAllowance) {
    return 4;
  }

  return null;
}

function isRetirementOverlapAdjustmentRequired(
  currentEvent: RetirementEvent,
  priorEvent: RetirementEvent
): boolean {
  const lookbackYears = getRetirementOverlapLookbackYears(currentEvent, priorEvent);

  if (lookbackYears === null) return false;

  // 同一年は合算
  if (lookbackYears === 0) return true;

  const yearDiff = currentEvent.year - priorEvent.year;

  return yearDiff >= 1 && yearDiff <= lookbackYears;
}
```

## 12. 重要補足：受取間隔ルール内でも控除がゼロになるとは限らない

### 12.1 結論

iDeCo一時金と会社退職金の受取間隔が、いわゆる「10年ルール」「20年ルール」などの範囲内に入ったとしても、**退職所得控除が一律でゼロになるわけではない**。

正確には、**重複している勤続期間・iDeCo加入者等期間に対応する退職所得控除額が調整される**。

したがって、シミュレーター上では以下のように扱う。

```text
受取間隔ルール内に該当する
= 退職所得控除が完全にゼロになる

ではない。

受取間隔ルール内に該当する
= 勤続期間・加入期間の重複を確認し、重複期間に対応する控除額を調整する
```

---

### 12.2 なぜゼロとは限らないのか

退職所得控除の重複調整は、同じ勤続期間・加入期間に対して、退職所得控除を二重に使わせないための仕組みである。

たとえば、以下のようなケースを考える。

```text
会社勤務期間：30年
iDeCo加入者等期間：20年
会社勤務期間とiDeCo加入者等期間が完全に重複している
```

この場合、会社退職金とiDeCo一時金を近い年に受け取ると、同じ20年分の期間について退職所得控除を二重に使うことになるため、重複調整が行われる。

一方で、以下のようなケースでは結果が変わる。

```text
会社勤務期間：30年
iDeCo加入者等期間：20年
重複している期間：10年
重複していない期間：10年
```

この場合、20年分すべてが消えるのではなく、重複している10年分を中心に控除調整を行う。  
重複していない期間に対応する控除は残る可能性がある。

---

### 12.3 実装上の考え方

重複調整は、以下の2段階に分ける。

```text
第1段階：
  受取年の差で、重複調整ルールの対象かどうかを判定する。

第2段階：
  対象の場合、会社勤務期間とiDeCo加入者等期間の重複を計算し、
  重複期間に対応する退職所得控除額を調整する。
```

つまり、以下のように実装する。

```ts
if (isRetirementOverlapAdjustmentRequired(currentEvent, priorEvent)) {
  const overlapPeriod = calculateServicePeriodOverlap(currentEvent, priorEvent);
  const adjustedDeduction = calculateAdjustedRetirementIncomeDeduction(
    currentEvent,
    priorEvent,
    overlapPeriod
  );
}
```

### 12.4 前回の退職金・iDeCo一時金が少額だった場合

前に受け取った退職手当等の金額が、前回の退職所得控除額に満たない場合、前回の勤続期間・加入期間を丸ごと重複期間として扱わない場合がある。

たとえば、以下のようなケースである。

```text
前回の退職所得控除額：800万円
前回の退職手当等の収入金額：300万円
```

この場合、前回の退職所得控除を使い切っていない。  
そのため、次回の退職所得控除を調整する際に、前回の勤続期間・加入期間をそのまま全部使ったものとして扱うのではなく、前回の収入金額に応じて短縮換算する考え方がある。

シミュレーターでは、最初の実装ではここを厳密計算しなくてもよいが、少なくとも以下の注意表示を出す。

```text
前回の退職手当等が少額で、前回の退職所得控除を使い切っていない場合、
重複調整額は通常より小さくなる可能性があります。
この画面の計算は概算です。
```

## 13. 実装上の注意

重複調整では、単純に「何年空けたか」だけで税額が決まるわけではない。最終的には以下が必要になる。

- それぞれの退職手当等の支給年
- 支給額
- 会社退職金の勤続期間
- iDeCo/DCの加入者等期間
- 両者の期間の重複
- 前回退職金が前回の退職所得控除を使い切っていたか

ただし、シミュレーターの最初の実装では、まず以下を優先する。

```text
第1段階:
  重複調整対象かどうかの判定
  ユーザーへの警告表示
  概算計算

第2段階:
  国税庁 No.2732 の詳細式に基づく厳密な重複期間・控除額調整
```
