## 実装目的

現在の一般向け版は、初回設定ウィザードは分かりやすい一方で、通常入力画面ではカードと入力欄が多く、ユーザーが次に何を入力すればよいか分かりにくい。

今回の目的は、次を実現することです。

- 必須入力、推奨入力、詳細入力、専門補正を画面上で区別する。
- 通常入力画面の上部に、入力状況と次アクションを表示する。
- PC画面を覆うように、すべてのカードを常時全体表示しない。
- 完了済みカードは要約だけ表示し、必要な時だけ展開できる。
- 計算に使っていないカードは全入力欄を表示せず、短い状態行にする。
- 入力完了後、次に必要なカードを枠色・ラベル・ボタンで促す。
- 未完了の必須カード、結果から指定されたカード、確認推奨カードを優先して開く。
- 結果画面やダッシュボードの注意表示から、該当する入力カードや根拠カードへ戻れる。

## 実装工程

### 1. 入力カード定義を追加

UI内で使う派生データとして、カード定義を作ってください。

最低限必要な概念:

- `id`
- `title`
- `priority`: `required` / `recommended` / `detail` / `expert`
- `status`: `not_started` / `incomplete` / `complete` / `review_recommended` / `not_applicable` / `inactive`
- `visibility`: `always` / `summary` / `collapsed` / `hidden`
- `highlight`: `none` / `current` / `next_required` / `review` / `blocked` / `targeted`
- `summary`
- `missingItems`
- `nextCardId`
- 対象タブ

保存データ構造を変える必要はありません。まずは既存のシナリオ状態から都度計算する形で構いません。

`status`、`visibility`、`highlight` は別々に扱ってください。

例:

- 入力済みの生活費: `status=complete`, `visibility=summary`
- 未入力の生活費: `status=incomplete`, `visibility=always`, `highlight=next_required`
- 年金プランナー反映中の外部公的年金イベント: `status=inactive`, `visibility=summary`
- 一般口座オプション未利用時の詳細: `status=not_applicable`, `visibility=hidden`

### 2. 入力状況サマリーを追加

`安全性シミュレーション` のサブタブ上部に、全入力タブ共通のサマリーを表示してください。

表示例:

- `必須入力: 5/7 完了`
- `次に入力: 生活費`
- `確認推奨: iDeCo一時金の加入期間`
- `結果は表示できます` または `主要入力が不足しています`

ボタン:

- `次の未入力へ`
- `結果を見る`
- `初回設定を開く`

`次の未入力へ` は対象タブへ切り替え、対象カードを展開し、該当カードへスクロールしてください。

### 3. 入力カードを折りたたみ化する

まずは次のタブを優先してください。

1. `初期資産`
2. `生活費`
3. `収入`
4. `基本情報`
5. `税・社会保険`

ルール:

- 各入力タブで、初期状態でフル表示するカードは原則1カードにする。
- 例外として、入力状況サマリー + 次に入力すべきカードの2つまでは許容する。
- それ以外のカードは、見出し、状態ラベル、主要値、`開く` ボタンだけを表示する。
- 未完了の必須カードは開く。
- 完了済みの標準カードは要約表示にする。
- 詳細、専門補正は初期状態で閉じる。
- ユーザーが明示的に開いたカードは、そのタブ内では開いた状態を維持する。
- 一度に多数のカードを自動展開しない。
- 収入イベント、特別支出、世帯メンバー、退職所得履歴などの繰り返しカードは、全件を初期展開しない。
- 繰り返しカードでは、編集中の1件、未入力がある1件、結果から指定された1件だけを展開する。

優先して折りたたむ領域:

- 初期資産: 取得原価・評価損益、資産別利回り、NISA投資計画、原資移動、取り崩し順、毎月追加投資、一般口座オプション用詳細
- 生活費: 費目別内訳、インフレ対象費目、年齢別生活費変更
- 収入: 年金受給プランナー、給与・パート、その他収入イベント、他シナリオ反映
- 税・社会保険: 詳細入力・専門補正、年度別根拠、月別明細、譲渡益課税根拠、所得水準別テーブル

特に対応すること:

- 年金受給プランナーを本計算へ `反映する` 設定の時、本人・配偶者の外部公的年金イベントは本計算に使われない。
- この場合、外部公的年金イベントカード全体を初期表示しない。
- 初期表示では、次のような短い状態行だけにする。

```text
計算対象外: 本人の公的年金イベント
年金受給プランナーを反映中のため、年金額と受給開始年月はプランナー側を使っています。
[詳細を開く] [プランナーを確認]
```

- 現在の長い注意文は、`詳細を開く` の中に移動する。
- `プランナーを確認` で年金受給プランナーカードへ移動できるようにする。
- 年金受給プランナーが `試算のみ` の場合、プランナー詳細は折りたたみ、外部公的年金イベントを標準入力として扱う。

### 4. カード要約を作る

折りたたみ時に、カードの主要値と状態を表示してください。

例:

- `完了: 現在資産 3,300万円`
- `要確認: iDeCo一時金の加入期間`
- `詳細未設定: 課税口座の取得原価`
- `任意: 税社保の通知書補正`

### 5. 次アクション導線を追加

各標準カードの末尾に、必要に応じて次のカードへ進むボタンを出してください。

例:

- `次へ: 初期資産を入力`
- `次へ: 生活費を入力`
- `次へ: 収入を入力`
- `結果を見る`
- `詳細設定を開く`

勝手にスクロールせず、ユーザーがボタンを押した時だけ対象カードへ移動してください。

カードの視線誘導:

- 入力後、次に必要なカードを `next_required` として扱う。
- 同じ画面内に次カードが見えている場合、カード枠をアンバー系で強調し、`次に入力` ラベルを出す。
- 次カードが別タブまたは画面外にある場合、現在カード末尾と入力状況サマリーに `次へ: 生活費を入力` のようなボタンを出す。
- 対象サブタブにも小さな `次` バッジを出す。
- ボタン押下後に対象カードを開き、スクロールし、数秒だけ強調状態にする。
- 色だけで意味を伝えず、必ず `次に入力`、`不足あり`、`確認推奨`、`計算対象外` などのラベルを併記する。

推奨の色意味:

- `編集中`: 青系
- `次に入力`: アンバー系
- `不足あり`: 赤系
- `確認推奨`: アンバー系の薄い表示
- `完了`: 緑系の控えめ表示
- `計算対象外`: グレー系
- `結果から遷移`: 青系の強調

### 6. 結果・ダッシュボードの初期表示を整理

結果画面とダッシュボードでは、初期表示を結論中心にしてください。

初期表示:

- 結論
- 次に確認すること
- 注意が必要な年

折りたたむ:

- 累計サマリー
- 投資計画チェック
- 税金・社会保険のキャッシュ支払タイミング
- NISA枠の詳細
- 月別収支表
- 年別収支表
- 原因調査用チャート

結果やダッシュボードの注意表示には、該当入力カードや根拠カードへ移動するボタンを追加してください。

例:

- `税社保の根拠を見る`
- `生活費を見直す`
- `iDeCo一時金の入力を確認`
- `取得原価を入力`

## 実装上の制約

- 一般向け版に、QNAP共有保存、実データ復旧、本人専用MVPなどの個人用文言を戻さない。
- 計算結果を変えない。今回はUX整理を主目的にする。
- 保存データの互換性を壊さない。
- 大きなリファクタリングをする場合でも、既存テストを通し、変更範囲を説明する。
- 可能なら小さなコンポーネントに分けるが、既存構造を壊すための抽象化は避ける。
