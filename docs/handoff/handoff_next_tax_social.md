## 6. 重要な設計判断

### 6.1 本質改善版は5175だけ

本質改善版は `http://127.0.0.1:5175/` です。

`5174` は従来版で、ユーザーは比較用に使っています。5174側を変更すると、比較基準が壊れます。

### 6.2 iDeCo年金は任意売却ではない

iDeCo年金受取は、取り崩し順に従う任意売却ではありません。

設計上は:

- 受取設定に従う予定受取元
- 年6回などの受取月に入金
- 源泉徴収を受取時に控除
- 雑所得として税・社会保険に反映

として扱います。

### 6.3 特定口座源泉徴収あり・申告しない

ユーザー方針:

```text
特定口座源泉徴収ありで申告しない場合は、原則として申告所得に入れない。
```

したがって、特定口座源泉徴収ありの売却益は、社会保険の所得判定に原則入れない設計です。

### 6.4 普通口座オプションは申告対象

普通口座オプションの損益は、確定申告が必要な所得として扱います。

設計上:

- 普通口座で発生した実現損益を年間集計
- 翌年の所得税精算、住民税、国保などに反映
- ただし表示上は、普通口座損益単独の参考税額と、全所得での実際の税社保を分ける

### 6.5 税・社会保険は前年所得ラグが重要

住民税、国保、後期高齢者医療などは、原則として前年所得に基づいて翌年に反映されます。

実装・検証時は、以下を混同しないこと。

- 所得発生年
- 申告年
- 支払年
- 保険料年度

### 6.6 NISAの扱い

ユーザーの基本思想:

- NISA積立中にNISAを売ってNISAへ再投資するのは矛盾。
- NISAはできるだけ取り崩し元から保護したい。
- 未実行分は可能なら翌年以降に繰り越して、枠が残っていて資金があれば実行したい。

実装済み・検討済み:

- NISA積立中はNISA売却を禁止または保護
- NISA年間枠チェック
- NISA未実行の表示
- NISA累計投資額・残り枠の見える化
- 未実行分の繰り越し

未検証の可能性:

- 普通口座終了時の証拠金戻しが、NISA未実行分へ適切に回るか
- 生活費・税社保優先後に余力があればNISAへ回るか

### 6.7 生活費変更

生活費は費目別に管理しています。

導入済み・検討済み:

- 年齢別生活費変更
- 費目別対象
- 同居状態変更
- 前年比倍率
- 期間固定倍率

注意:

- 前年比倍率を期間にかけると毎年累積で減りすぎるため、ユーザーには不向き。
- 「70代は60代比95%」のような入力には、期間固定倍率または基準年比率の方が向いています。

### 7.2 申告分離譲渡益税翌年支払分が0円に見える問題

ユーザーは、普通口座オプション利益に対する税額を明示的に見たいと希望しています。

現在の問題:

- `申告分離譲渡益税翌年支払分` や `翌年譲渡益税源泉なし等` が0円で並ぶ。
- 一方で普通口座オプション損益は、全所得ベースの所得税・住民税・国保に入っている。
- そのため、普通口座損益に由来する税負担が見えにくい。

改善案:

- 0円列は削除または非表示にする。
- 別表で以下を表示する。
  - 普通口座申告対象損益
  - 参考所得税等 15.315%
  - 参考住民税 5%
  - 参考合計 20.315%
  - 全所得ベースでの実際の翌年税社保増分
- 「参考税額」と「実際の税社保」は別物として明示する。

### 7.3 国民年金の金額が高く見える問題

ユーザーの疑問:

- 本人は60歳以降は国民年金を払わないはず。
- 配偶者分だけ残るはず。
- 年額43万円が表示されるのは、夫婦2人分になっていないか、支払期間が長すぎないか。

次に確認すべきこと:

- 世帯メンバー別の国民年金支払対象年齢
- 本人と配偶者の生年月日
- 任意加入扱いが入っていないか
- 年度途中の60歳到達月をどう月割りしているか
- 国民年金欄が世帯合計なのか個人別なのか

表示改善案:

- 国民年金を個人別に分解する表を追加する。
- 年度、本人、配偶者、その他、合計を表示する。

### 7.4 流動資金という言葉の分かりにくさ

ユーザーは「現金」「普通預金」「銀行預金」「流動資金」の関係を混乱しやすい。

現在の整理:

- 流動資金 = 現金 + 普通預金
- 生活費やカード引き落としは実質的に普通預金から出る
- オプション口座から普通預金へ戻した利益は、外部収入ではなく内部移動

改善案:

- 表記を `流動資金（現金・普通預金）` に統一する。
- 年始・年末の流動資金を表示する。
- 外部収入と内部移動を分ける。

### 7.5 入力遅延・重さ

ユーザーは、入力欄の反応が遅いと感じています。

原因候補:

- 入力ごとに全シナリオ・全期間のシミュレーション再計算が走っている。
- 大量の表・チャートが毎入力で再描画されている。
- LocalStorage保存も入力ごとに重い可能性。

改善案:

- 入力 state とシミュレーション state を分離する。
- debounce を入れる。
- 結果タブ以外では重い表を計算しない。
- `useMemo` の依存を見直す。
- 表の行数を仮想化または折りたたむ。
