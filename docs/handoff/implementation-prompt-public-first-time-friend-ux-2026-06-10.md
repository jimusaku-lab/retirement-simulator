# 実装担当向けプロンプト: 友人テスト前の初回UX改善

あなたは実装担当です。一般向け版を友人に試してもらう前に、初めて触るユーザーが迷わない入力UXへ改善してください。

- `docs/public-app/ux-guided-input-card-collapse-design.md`

## 1. サンプル由来の毎月追加投資を初回設定後に残さない

現状、初期サンプルに `NISA積立` 月5万円が入っている。

問題:

- 初回設定ウィザードでは追加投資を入力していない。
- しかし `applyOnboardingDraftToScenario` が `assetContributionEvents` を初期化しないため、サンプル由来の追加投資が残る。
- 初めてのユーザーは、自分で入力していない積立が計算に入っていることに気づけない。

実装:

- `applyOnboardingDraftToScenario` で `scenario.assetContributionEvents = []` にする。
- もしくは、ウィザードに `毎月の積立予定` を明示的に追加し、その入力値だけで `assetContributionEvents` を作る。
- 友人テスト前は、まずクリア方式でよい。

受け入れ条件:

- 初回設定を保存した直後、追加投資予定は0件。
- 資産タブの `毎月の追加投資` に、ユーザーが入力していないNISA積立が残らない。

## 2. 「毎月の追加投資」の表示名と説明を変更

現状:

- `毎月の追加投資`
- 初期資産タブ下部にあり、現在資産と混同しやすい。

変更:

- 見出し: `将来の積立予定`
- 補足: `現在の資産額ではなく、開始月以降に毎月投資する予定額です。生活費・税社保を払った後の資金から実行されます。`
- 0件の場合: `積立予定はまだありません。NISA積立などを将来も続ける場合だけ追加します。`

追加:

- 入力状況サマリーに、追加投資がある場合だけ `積立予定あり` と表示する。
- 追加投資の原資不足が結果に出る場合、結果からこのカードへ戻れるようにする。

## 3. 生活費の「その他」を未分類として扱う

実装:

- `monthlyExpenses.other` が生活費合計の50%以上なら、入力ガイドに `確認推奨: 生活費の内訳` を出す。
- 生活費タブ先頭の説明を強める。
- `その他` ラベルの横に、条件付きで `未分類が多め` を表示する。
- ボタンを追加する。
  - `ざっくりのまま進む`
  - `費目別に分ける`

可能なら追加:

- `食費・日用品・光熱費へざっくり分ける` のクイック分解ボタン。
- 分解後も月平均生活費合計は変えない。

受け入れ条件:

- ウィザードで生活費32万円、住宅8万円、医療1.5万円の場合、残り22.5万円が `その他` に入るが、通常入力では `未分類が多め` と表示される。
- 必須未完了にはしない。確認推奨にする。

## 4. 特別支出タブから資産活用へ誘導

現状、タイムバケットから特別支出へ変換する機能はあるが、特別支出タブから見た導線が弱い。

実装:

- `SpecialSection` の先頭に `やりたいことから作る` カードを追加する。
- 特別支出0件、または楽しみカテゴリ0件の場合は強調表示する。
- ボタン: `資産活用でやりたいことを整理`
- クリックで `assetUse` モード、`timeBucket` タブへ移動する。

文言例:

```text
旅行・趣味・家族イベントなどは、資産活用のタイムバケットで整理してから、計算に入れるものだけ特別支出に変換できます。
```

受け入れ条件:

- 安全性シミュレーションの特別支出タブから、資産活用のタイムバケットへ迷わず移動できる。
- タイムバケット由来の特別支出は、特別支出側で由来が分かる。

## 5. 初期サンプル値を友人テスト向けに調整

現状の標準ケースは、資産寿命が73歳台、90歳残高が大きくマイナスになりやすい。

変更方針:

- `標準ケース` は、90歳時点で目標残高を少し上回る程度にする。
- 厳しめのケースは別シナリオに分ける。
- `標準ケース` の説明に `入力練習用の匿名サンプル` と明記する。

注意:

- 計算を甘くするのではなく、初期サンプルを「成立する例」にする。
- 厳しいケースは比較用として残してよい。

受け入れ条件:

- 初回表示の標準ケースで、いきなり大幅ショートしない。
- ダッシュボードで `これは入力練習用の匿名サンプルです` が分かる。

## 6. 収入入力をユーザー状態に応じて変える

最低限の実装:

- ウィザードの家族ステップまたは収入ステップに `現在の状態` を追加する。
  - `退職前`
  - `退職済み`
  - `退職後も働く`
  - `年金生活中`
- `退職前` の場合、収入ステップでは `給与・賞与/退職予定/退職金/年金/iDeCo` の順に見せる。
- `退職済み` の場合、`年金/iDeCo/その他収入` を優先する。

初回リリースでは、入力順と説明文だけ変えればよい。データモデルの大変更は不要。

## 7. 税・社会保険の申告確認を変化点表示へ

対象:

- `TaxFilingAdviceSummary`

実装:

- 初期表示では `attention` と `review` の行だけを前面に出す。
- `notRequiredLikely` が連続する年度は範囲でまとめる。
- 全年度表は `全年度の判定表を開く` の中へ移す。

受け入れ条件:

- 年金以外所得20万円超の年など、確認すべき年が埋もれない。
- 同じ文言が年ごとに長く並ばない。

## 8. 初回設定への常設導線

実装:

- ヘッダー操作、または入力ガイド内に `初回設定をやり直す` を常設する。
- 左下固定ボタンは残してもよいが、主導線にしない。
- `データ` タブにも `初回設定をやり直す` を置く。

受け入れ条件:

- ユーザーがウィザードを閉じた後でも、画面上部から再開できる。

## 9. 入力ガイド文言の微修正

現状例:

```text
必須入力は完了。次に確認するとよいとして iDeCo受取 を確認すると試算の精度が上がります。
```

変更例:

```text
必須入力は完了しています。次に確認するとよい項目は「iDeCo受取」です。
```

ボタン:

- `iDeCo受取を確認する`
- `入力状況を開く`

## QA

必ず実行:

```bash
npm --prefix apps/retirement-life-planner-public run test -- src/lib/simulation.test.ts
npm --prefix apps/retirement-life-planner-public run build
```

ブラウザ確認:

- 初回起動
- データの扱い確認
- 初回設定ウィザード全ステップ
- 初回設定保存後の資産タブ
- 生活費タブの `その他` 表示
- 特別支出タブから資産活用へ移動
- 税・社会保険タブの申告確認
- PC幅とスマートフォン幅

確認項目:

- 初回設定保存後、サンプル由来のNISA積立が残らない。
- 追加投資の意味が現在資産ではなく将来積立だと分かる。
- 生活費の `その他` が大きい時、未分類として確認推奨になる。
- 特別支出タブで、資産活用・タイムバケットから作る流れが分かる。
- 標準ケースが初回から大幅ショートしない。
- ウィザードの再開場所が分かる。
- 税・社会保険の確認表で、注意年だけが見つけやすい。
