# 改善フェーズ4 引き継ぎレポート

作成日: 2026-05-16  
対象アプリ: `apps/retirement-life-planner` 退職後生活シミュレーション  
直近の安定コミット: `9b3faca3 Add special expense inflation settings`

## 目的

フェーズ4では、フェーズ3で追加した「資産を守る」だけでなく「資産を有効に使う」観点をさらに発展させる。別スレッドで導入されたタイムバケット・プランナーとの統合も含め、現状の設計・実装状態・注意点を次の設計担当者へ渡す。

## 現在の大きな構成

アプリは大きく2系統になっている。

- 安全性シミュレーション
  - 既存の退職後資産維持、税・社会保険、収入、生活費、特別支出、比較、結果確認の本体。
  - 資産寿命、目標残高、最低流動資金、NISA、iDeCo、普通口座オプション等を含む。

- 資産活用ビュー
  - 同じ計算結果を使い、健康寿命期にどれだけ資産を有効利用できるかを見るビュー。
  - Die with Zero 的な「楽しみ支出」「使える余地」「入金力と税社保効率」「タイムバケット」の入口。

重要な方針は、計算エンジンを二重化しないこと。資産活用ビューも安全性シミュレーションと同じ `simulateScenario` の結果を読む。

## フェーズ3で実装済みの主な改善

### 1. 資産活用ビュー

主な追加・整理:

- 資産活用レビュー
- 楽しみに使える額を探すクイック試算
- 入金力別診断
- 普通口座オプションの流動資金化
- 特別支出内の楽しみ比率
- 健康寿命期の支出内訳
- 判定前提の折りたたみ整理

ユーザー目線では、最初に全体の安全余力を見て、次にクイック試算または入金力別診断に進む設計にした。

### 2. 入金力別診断

普通口座オプション収入イベントを対象に、月0〜50万円などの仮の入金力を置いた場合の以下を比較する。

- 入金総額
- 税・社会保険増分
- 実質手残り
- 有効率
- 楽しみに増やせる年額
- 90歳目標差額
- 資産寿命

過去に、普通口座オプション収入イベントのサブ口座紐付けや、基準イベントが0円の時の診断挙動で混乱があった。現在は計算入力チェックを入れ、どのイベントが診断対象になっているか見えるようにした。

### 3. シナリオ間コピー機能

以下のタブに、他シナリオへ前提を反映する機能を追加済み。

- 初期資産
- 生活費
- 収入
- 特別支出

安全策:

- コピー元シナリオを選べる。
- 反映先を比較対象または全シナリオから選べる。
- 現在開いているシナリオを誤って上書きしないオプションがある。
- 収入では、コピーする収入イベントを選択できる。
- 実行前に確認ダイアログを出す。
- 実行前の状態は履歴バックアップに残る。

注意:

- コピーは便利だが、誤操作リスクが高い。フェーズ4ではコピー操作の視認性・差分確認・取り消し導線を強化するとよい。

### 4. 特別支出機能の拡張

特別支出はフェーズ3後半で大きく強化された。

実装済み:

- カテゴリ
  - 楽しみ
  - 生活維持
  - 住宅・車
  - 医療・介護
  - 家族支援
- カードの任意並べ替え
  - 順番セレクト
  - 上へ / 下へ
  - 複製時は複製元の直下に挿入
- 並べ替え後の順序は、他シナリオへコピーした場合もそのまま反映
- 毎年の指定月だけ毎月発生
  - 例: ハイキングを毎年3月〜11月だけ発生
  - 開始年月・終了年月と、発生開始月・発生終了月の両方で判定
- 特別支出カードごとのインフレ設定
  - 反映しない
  - 生活費インフレ率を使う
  - 医療インフレ率を使う
  - 個別指定

安全設計:

- 既存データの結果が勝手に変わらないよう、初期値は `反映しない`。
- インフレを選んだカードだけ、支出発生月まで年率で金額を膨らませる。
- 資産活用ビューのカテゴリ集計にも、インフレ後金額を反映する。

入力方針:

- 冷蔵庫、洗濯機、エアコンなどの耐久消費財は通常 `生活維持`。
- 金額は「当時の購入価格」ではなく、「入力時点で同等品を買うならいくらか」を入れる。
- 将来価格にしたい場合は、カードごとの `インフレ反映` を使う。

### 5. 表示整理

結果・比較・税社保などの詳細情報が多くなったため、以下を整理した。

- 比較タブに「このタブで見ること」「最初に見る列」「原因を見る時」の案内を追加
- 詳細比較やチャートは折りたたみへ
- 結果タブの累計サマリーを折りたたみへ
- 税・社会保険の詳細根拠を折りたたみへ
- コピー機能の見出しを `他シナリオへ反映（必要時のみ）` に変更

### retirement-life-planner への統合案・導入状態

`src/components/TimeBucketPlanner.tsx` と `src/App.tsx` の差分を見る限り、以下の統合が進んでいる。

- 資産活用ビュー内にサブタブを追加
  - 資産レビュー
  - クイック試算
  - タイムバケット

1. 作業ツリー確認

```bash
git status --short

```

タイムバケット統合が未コミットのままなら、まずビルド・テストを通してから専用コミットにする。

2. 型と保存データ互換性

`ScenarioData` に `timeBucketItems` が追加されているため、既存LocalStorageデータの正規化が重要。`normalizeScenario` で `timeBucketItems` を空配列に補完する処理は入っている。

確認ポイント:

- 既存保存データでアプリが落ちないか
- JSONインポート時に `timeBucketItems` がなくても問題ないか
- サンプルデータに `timeBucketItems: []` が入っているか

3. 計算への影響

タイムバケット項目そのものは計算に入れない。変換後の特別支出のみ計算される。これは維持すること。

4. UIの位置づけ

資産活用ビュー内の「タイムバケット」は、クイック試算や入金力別診断とは目的が違う。

- タイムバケット: 何をしたいかを整理する
- 特別支出: いつ、いくら使うかを計算に入れる
- クイック試算: 追加支出額が安全かを試す
- 入金力別診断: 収入増加で楽しみ支出を増やせるかを見る

フェーズ4では、この関係を画面内で自然に理解できるようにすることが重要。

## フェーズ4の推奨設計テーマ

### A. タイムバケットと特別支出の往復改善

現状は「タイムバケット → 特別支出へ変換」が中心。次は以下を検討するとよい。

- 変換後の特別支出をタイムバケット側から編集できるか
- 特別支出側で変更した金額・年月がタイムバケット側にどう見えるか
- 変換済みリンクが壊れた時の扱い
- タイムバケット項目を削除した時、特別支出も削除するかは明示確認が必要
- 特別支出を削除した時、タイムバケット側の `convertedSpecialExpenseId` をどう掃除するか

安全策:

- 自動削除は避ける
- 削除・解除は確認ダイアログを出す
- 「リンク解除」と「支出削除」を分ける

### B. タイムバケットから支出化する時の入力支援

今後欲しい入力補助:

- 実施年齢から年月を自動提案
- 単発 / 毎年 / 季節指定の選択
- 金額の現在価格・将来価格の扱い説明
- インフレ反映の初期提案
  - 旅行: 反映しない、または生活費率
  - 医療・介護: 医療率
  - 家電・生活維持: 生活費率
- カテゴリは基本 `楽しみ` だが、ユーザーが変えられるようにする

### C. 資産活用ビューのストーリー整理

資産活用ビューは今後さらに増えるため、情報設計を明確にする。

推奨順序:

1. まず「何をしたいか」: タイムバケット
2. 次に「いくら・いつ使うか」: 特別支出化
3. 次に「安全か」: クイック試算・資産活用レビュー
4. 最後に「収入を増やす価値があるか」: 入金力別診断

この流れを画面上でも表現すると、ユーザーの迷いが減る。

### D. コピー機能の誤操作予防

フェーズ3でコピー機能は入ったが、今後タイムバケットもコピー対象にするかは慎重に設計する必要がある。

検討事項:

- タイムバケット項目だけコピーするか
- 変換済み特別支出も一緒にコピーするか
- `convertedSpecialExpenseId` をコピー先でどう再生成するか

推奨:

- 最初はタイムバケットコピーを独立機能にする
- 特別支出とのリンクIDはコピー先で再生成する
- 「タイムバケットだけ」「特別支出も含める」を明示選択にする

### E. レスポンス改善

フェーズ3中、資産活用ビューに診断が増えたことで重くなった場面があった。現在は診断実行ボタンや折りたたみで緩和しているが、フェーズ4では以下を検討する。

- 入金力別診断を完全に明示実行・結果キャッシュ化
- タイムバケット操作時に不要な `simulateScenario` 再計算を避ける
- 資産活用ビュー内で表示していないサブタブの重い計算を走らせない
- 大きなチャートや詳細表を遅延レンダリング

## 計算ロジック上の注意点

### 特別支出インフレ

現在の安定版では、特別支出カードごとにインフレ設定を持つ。

入力金額は「シミュレーション開始月時点の価格」として扱う。発生月まで以下の年率で膨らませる。

- 生活費インフレ率
- 医療インフレ率
- 個別指定率

既存データは `反映しない` なので、勝手に結果は変わらない。

### 季節指定の特別支出

`seasonalMonthly` は、開始年月・終了年月の範囲内で、指定月範囲に該当する月だけ発生する。

例:

- 開始年月: 2026-05
- 終了年月: 2045-11
- 発生開始月: 3月
- 発生終了月: 11月

この場合:

- 2026年は5月〜11月
- 2027年以降は3月〜11月
- 終了年は終了年月まで

### 資産活用ビューのカテゴリ集計

特別支出のカテゴリ別集計は `calculateSpecialExpenseCategoryTotals` を使う。インフレ後金額もこの集計に反映される。

## フェーズ4担当者への最重要注意

- 計算ロジックは金融・税社保・資産寿命に直結するため、UI変更でも必ず既存テストを回す。
- タイムバケットは「計算前の願望整理」、特別支出は「計算に入る支出」。この境界を曖昧にしない。
- ユーザーが誤って全シナリオの収入・特別支出を上書きした経験があるため、コピー・削除・変換は必ず予防UIを入れる。
- 新機能は既存シナリオの結果を勝手に変えない初期値にする。
- 「楽しみ支出を増やせるか」をユーザーが一目で判断できることが、フェーズ4の中心価値。
