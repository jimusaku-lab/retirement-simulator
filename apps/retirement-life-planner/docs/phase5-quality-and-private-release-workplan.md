## 2. フェーズ5 品質仕上げ

### 2.1 タイムパケット退職後プラン対応

目的:

- 50代後半から60代のユーザーにとって、10年単位の箱が粗すぎる問題を解消する。
- 健康なうちにやることを、2年単位で具体化できるようにする。

実装タスク:

- `TimeBucketBucketId` の固定年代型に依存しすぎない構造へ寄せる。
- バケット定義を動的に生成できる形にする。
- 表示モードを追加する。
  - 年代モード
  - 退職後プランモード
- 50歳以上、または資産活用集計期間が設定されている場合は、退職後プランモードを初期表示にする。
- 退職後プランモードでは、以下の箱を表示する。

```text
やりたいことリスト
今すぐ・準備中
60〜61歳
62〜63歳
64〜65歳
66〜67歳
68〜69歳
70〜72歳
73歳以降
保留・やらない
```

完了条件:

- 退職後プランモードで上記の箱が表示される。
- 年代モードも既存データ確認用として残る。
- 既存保存データの `todo`、`50s`、`60s` などが読み込める。
- 既存データを無理に自動移行しない。必要なら手動で置き直せる表示にする。

### 2.2 楽しみ支出への変換初期値

目的:

- 箱に置いた予定を、自然な実施年月で楽しみ支出へ変換できるようにする。

実装タスク:

- バケットに `startAge`、`endAge`、`defaultYearMonthAge` 相当の情報を持たせる。
- 楽しみ支出へ変換する時、実施年月の初期値を箱の開始年齢に合わせる。
- `今すぐ・準備中` はシミュレーション開始年月を初期値にする。
- `保留・やらない` は支出化ボタンを非表示、または確認を挟む。

完了条件:

- `60〜61歳` の項目を変換すると、本人が60歳になる月が初期実施年月になる。
- `66〜67歳` の項目を変換すると、本人が66歳になる月が初期実施年月になる。
- `70〜72歳` の項目を変換すると、本人が70歳になる月が初期実施年月になる。

### 2.3 譲渡益課税根拠表示の整理

目的:

- 「課税・申告に影響する行」と「課税されない資金移動」を分け、ユーザーの誤解を減らす。

実装タスク:

- 初期表示は以下のいずれかに該当する行を中心にする。
  - `taxWithheld > 0`
  - `deferredTax > 0`
  - `declaredIncome > 0`
- `grossWithdrawal > 0` だが、`realizedGain = 0` かつ `taxWithheld = 0` の行は、別の折りたたみへ分ける。
- 普通口座オプションの表示を、以下の意味で見分けられるようにする。
  - 利益発生: 申告対象損益
  - 資金移動: すでに課税対象化済みの原資移動

完了条件:

- 税・社会保険タブで、課税対象と非課税移動が混ざって大量に見えない。
- 「課税なし」の行を確認したい場合は折りたたみから見られる。

### 2.4 ダッシュボード過密部分の整理

目的:

- ダッシュボードを「判断画面」として維持し、原因調査用の詳細を前面に出しすぎない。

実装タスク:

- 年別の流動資金フローを折りたたみ、または結果タブ寄りの表示にする。
- 「生活・税社保支出」は要約、「資産活用ウォーターフォール」は根拠であることが伝わる文言へ調整する。
- 楽しみ支出が0円の場合、タイムパケットまたはクイック試算へ誘導する表示を追加する。

完了条件:

- ダッシュボード上部の判断情報が埋もれない。
- 楽しみ支出が未登録の場合、次に何を入力すればよいか分かる。

## 6. 関係者限定デプロイ

GitHub安全化後に実施する。

目的:

- ローカルPCだけでなく、自分、妻、関係者がブラウザで見られる状態にする。

推奨:

- GitHub Pages単体ではなく、アクセス制御できるホスティングを優先する。
- 候補はVercel、Netlify、Cloudflare Pagesなど。
- 最初は一般公開ではなく、ログインまたはパスワード保護付きの限定公開にする。

実施タスク:

- ホスティング先を1つ選ぶ。
- GitHub Private repoと連携する。
- ProductionまたはPreviewのアクセス制御を設定する。
- 環境変数やAPIキーが不要な静的アプリとして配信する。
- URLを自分と妻で確認する。

完了条件:

- 自分のPC以外からアプリURLを開ける。
- 許可された人だけが見られる。
- 未許可の人は見られない。
- アプリ内に個人資料ファイルが同梱されていない。
