作成日: 2026-05-16  
対象アプリ: `apps/next-tax-social` 退職後生活シミュレーション  
参照資料:

- `docs/handoff-phase4-current-state.md`

## 1. フェーズ4の結論

フェーズ4の主目的は、新しい計算エンジンを増やすことではなく、既に計算されている結果を「本人が誤解なく意思決定できる画面」に再構成すること。

最優先で入れるべき改善は次の3つ。

1. シナリオ差分パネル
2. ダッシュボードの読み順と用語整理
3. 比較タブの主要列の絞り込み

タイムバケット統合は重要だが、現時点では未コミット差分を含むため、フェーズ4の本体実装前に安定化対象として扱う。フェーズ4で深追いする範囲は「願望整理から特別支出化までの安全な導線」に絞る。

## 1.1 原稿版を読んだ上での追加判断

原稿版では、ダッシュボード、資産レビュー、クイック試算、タイムバケット、比較タブの骨格は既にできている。したがってフェーズ4は、画面を作り直すより、既存画面の読み順と情報量を調整する改善にする。

原稿版で確認した具体的な課題:

- ダッシュボードの主要カードは良いが、「資産残高と取り崩しの推移」で資産残高と年間取り崩しが同じチャートに載っており、資産活用額との混同が残る
- ダッシュボードに「集計期間の変更は比較タブで行います」と出ており、ダッシュボードの前提なのに比較タブへ行く必要があるように見える
- 資産活用ビューのサブタブ順が `資産レビュー -> クイック試算 -> タイムバケット` になっているが、本人の意思決定順としては `タイムバケット -> クイック試算 -> 資産レビュー` の方が自然
- 資産レビューには「まず安全性と使える余地を確認し、次にクイック試算か入金力別診断へ進む」という導線があるが、「何をしたいか」を整理するタイムバケットへの誘導が弱い
- 比較タブは基準シナリオ選択がなく、詳細比較では先頭シナリオを暗黙の基準にしている
- 比較タブの主要表に、意思決定列と原因調査列が同列で並んでいる
- タイムバケットは追加・年代移動・特別支出化の基本はできているが、支出化前後のリンク解除、削除時の確認、インフレ設定、カテゴリ変更がまだ弱い

このため、フェーズ4の設計は次の順で優先する。

1. 比較タブに明示的な基準シナリオと差分要約を入れる
2. ダッシュボード上部に基準との差分要約を入れる
3. ダッシュボードのチャートから「取り崩し」を主表示から外し、資産残高推移と資産活用ウォーターフォールに分ける
4. 資産活用ビューの導線を `何をしたいか -> いくら使うか -> 安全か -> 収入を増やす意味はあるか` に並べ直す
5. タイムバケットから特別支出化する時の安全確認と入力補助を強化する

## 2. 設計原則

### 2.1 計算は二重化しない

安全性シミュレーション、資産活用ビュー、比較タブ、タイムバケット由来の特別支出は、すべて同じ `simulateScenario` の結果を読む。

追加するのは、入力差分を読むための比較関数、表示用サマリー、チャート用データ整形に限定する。

### 2.2 入力条件と結果を分けて見せる

比較結果を見る前に、各シナリオが基準と何が違うかを見せる。

これにより、90歳残高や資産寿命の差を見たあとに、収入・特別支出・NISA・iDeCo・普通口座オプションのタブを何度も往復しなくて済む。

### 2.3 「資産活用額」と「取り崩し」は別物として扱う

資産活用額は、健康寿命期の生活費・税社保・特別支出を現金収入等で賄えず、資産で補った額。

取り崩しは、シミュレーション内部で不足補填、収入化した原資、計画取り崩し、投資原資不足などを含む広い資産移動。ダッシュボードでは混ぜて表示しない。

### 2.4 タイムバケットは計算前、特別支出は計算対象

タイムバケットに置いただけでは計算に入れない。明示的に特別支出へ変換した項目だけを計算対象にする。

削除・リンク解除・コピーでは、自動削除を避け、ユーザーに選択させる。

## 4. シナリオ差分設計

### 4.1 目的

「このシナリオは基準と何が違うか」を、結果表の前に見せる。

### 4.2 表示場所

比較タブ上部:

- 基準シナリオ選択
- 比較対象ごとの差分表
- 詳細差分の折りたたみ

ダッシュボード上部:

- 現在選択中シナリオと基準シナリオの差分を3から5行で要約
- 基準シナリオは比較タブと同じ選択を使う

### 4.3 状態管理

追加する状態:

```ts
baselineScenarioId: string
```

保存場所の候補:

- 最小実装: `App` の `useState`
- 永続化する場合: `RetirementPlanState` に追加

本人用完成版では、アプリを開き直した時にも基準が残る方が便利なため、永続化を推奨する。ただし既存保存データ互換のため、未設定時は `compare` 対象の先頭、なければ先頭シナリオを基準にする。

### 4.4 差分データ型

新規ファイル候補:

```text
src/lib/scenarioDiff.ts
src/lib/scenarioDiff.test.ts
```

型:

```ts
export type ScenarioDiffSeverity = "same" | "changed" | "added" | "removed";

export type ScenarioDiffItem = {
  id: string;
  category:
    | "income"
    | "retirementIncome"
    | "nisa"
    | "ideco"
    | "specialExpense"
    | "monthlyExpense"
    | "taxSocial"
    | "optionAccount"
    | "timeBucket";
  label: string;
  summary: string;
  baselineValue?: string;
  targetValue?: string;
  severity: ScenarioDiffSeverity;
};

export type ScenarioDiffSummary = {
  baselineScenarioId: string;
  targetScenarioId: string;
  headlineItems: ScenarioDiffItem[];
  items: ScenarioDiffItem[];
};
```

優先度Aで比較する項目:

- 収入イベント
- iDeCo受取に関わる収入イベント
- NISA投資ルール
- 特別支出
- 生活費合計と年齢別調整
- 税・社会保険の計算モード

優先度Bで追加する項目:

### 4.6 差分キー

既存データはシナリオ複製・コピーで `id` が維持される場合と再生成される場合があるため、差分キーは `id` だけに依存しない。

収入イベント:

- 第一候補: `id`
- 第二候補: `name + type + memberId`

特別支出:

- 第一候補: `id`
- 第二候補: `name + yearMonth + category`

NISA、税社保、普通口座オプション:

- 設定オブジェクト単位でフィールド比較

### 4.7 要約ルール

ダッシュボードでは全差分を出さず、影響が大きいものを優先する。

優先順位:

1. 収入の追加・削除・期間短縮
2. 普通口座オプション収入月額・反映先の変更
3. iDeCo受取年数・受取方式の変更
4. NISA月額・枠・未実行繰越設定の変更
5. 特別支出の追加・削除・金額変更
6. 生活費合計の変更
7. 税社保計算モードの変更

表示例:

```text
基準との差分
- 妻パート: 2027年分なし
- 米国株オプション: 月10万円を口座内積上
- iDeCo受取: 5年 → 10年
```

### 5.1 読み順

ダッシュボードは次の順に並べる。

1. 選択シナリオと基準との差分
2. 現在資産
3. 資産寿命 / 90歳残高
4. 60から72歳 資産活用額
5. 72歳時点残高
6. 60から72歳 楽しみ支出
7. 60から72歳 生活・税社保・源泉/譲渡益税支出
8. 60から72歳 その他特別支出
9. NISA実行額 / 残り枠

既存の主要8カードは維持する。ただし、カードの文言を調整する。

### 5.1.1 集計期間設定の扱い

原稿版では「集計期間の変更は比較タブで行います」と表示されている。これは本人用アプリとしては少し遠回りに見える。

推奨は、集計期間をアプリ共通の前提として見せること。

短期実装:

- ダッシュボードの「資産活用集計期間」カード内に、現在の開始年齢・終了年齢を表示する
- 変更ボタンは比較タブではなく、同カード内か基本情報の該当欄へ誘導する

中期実装:

- `FlexibleFreeCashPeriodFields` を共通コンポーネント化し、ダッシュボード、資産活用ビュー、比較タブのどこからでも同じ期間を編集できるようにする

文言:

```text
この期間は、ダッシュボード・資産活用ビュー・比較タブで共通に使います。
```

### 5.2 文言変更

資産活用額:

```text
生活費・税社保・特別支出を、現金収入だけで賄えず資産で補った額
```

生活・税社保支出:

```text
生活費、税社保、譲渡益税、iDeCo源泉の合計
```

チャート名:

現状の「資産残高と取り崩しの推移」は分割する。

- 資産残高推移
- 取り崩し・資産移動の詳細

ダッシュボードでは前者を主表示にする。後者は結果タブまたは折りたたみへ寄せる。

原稿版では「年別の流動資金（現金・普通預金）フロー」に追加投資も入っている。これは原因調査としては有用だが、資産活用額の説明とは別の話なので、ダッシュボードでは次の扱いにする。

- 主表示: 資産残高推移、資産活用ウォーターフォール
- 折りたたみ: 年別の流動資金フロー、追加投資、原資移動
- 結果タブ: 取り崩し、NISA未実行、不足補填売却の詳細

## 7. タイムバケット設計

### 7.1 役割

タイムバケットは「何をしたいか」を整理する場所。計算に入れる場所ではない。

計算に入れる時は、明示的に特別支出へ変換する。

### 7.1.1 資産活用ビュー内の順番

原稿版ではサブタブが `資産レビュー -> クイック試算 -> タイムバケット` の順に並んでいる。

フェーズ4では次の順を推奨する。

1. タイムバケット
2. クイック試算
3. 資産レビュー
4. 入金力別診断

理由:

- タイムバケット: 何をしたいかを決める
- クイック試算: 年額や期間を仮置きする
- 資産レビュー: 実際の計画として安全かを見る
- 入金力別診断: 収入を増やす意味があるかを見る

ただし、初回表示は現在の「資産レビュー」のままでもよい。変更する場合は、タイムバケットが空の時だけ「まず候補を入れる」導線を強くし、既に特別支出が十分登録されている時は資産レビューを初期表示にする。

### 7.2 変換UIの改善

現状の変換項目に追加する。

- カテゴリ選択
- インフレ反映
- 単発 / 毎年 / 毎年指定月
- 実施年齢から年月提案
- 金額の扱い説明

初期値:

- カテゴリ: `楽しみ`
- インフレ: `反映しない`
- 計算方式: `単発`

インフレは勝手に入れない。ユーザーが選んだ時だけ結果を変える。

原稿版の変換フォームには、実施年月、金額、計算方式、終了年月、メモがある。ここに追加する最小項目は次の3つ。

- カテゴリ
- インフレ反映
- 特別支出タブへ移動せずリンク先を確認する要約

支出化後に表示する要約:

```text
支出化済み: 2030/05 単発 50万円 楽しみ インフレ反映なし
```

この要約があれば、タイムバケット側で「計算に入っているか」「いつ・いくらで入っているか」を確認できる。

### 7.3 リンク管理

`TimeBucketItem.convertedSpecialExpenseId` は維持する。

追加する操作:

- 特別支出を見る
- リンク解除
- 特別支出を削除

削除時のルール:

- タイムバケット項目削除時、変換済み特別支出は自動削除しない
- 削除確認で「タイムバケットだけ削除」「リンク先の特別支出も削除」を選ばせる
- 特別支出削除時、対応する `convertedSpecialExpenseId` を消す

### 7.4 コピー

タイムバケットの他シナリオコピーは、特別支出コピーと分ける。

選択肢:

- タイムバケットだけコピー
- タイムバケットと変換済み特別支出をコピー

後者では、コピー先で新しい特別支出IDを発行し、`convertedSpecialExpenseId` を再紐付けする。

## 8. 税・社会保険表示

優先度Cで入れる。

追加表示:

- 税社保計算の年度ラベル
- 料率が何年度前提か

ここは計算式を広げるより、前提と警告を明確にする。
